# Оптимизация времени компиляции SchemeShard

## Результат

Оптимизированы все 216 активных C++-компиляций таргета
`ydb/core/tx/schemeshard`.

Воспроизводимый итоговый выигрыш:

- **1.31× по суммарному CPU-времени** — снижение на 23.5%;
- **1.36× по wall-clock** — снижение на 26.2%;
- **1.38× по медиане времени одного C++ compile action**;
- **1.22× по p95 времени одного C++ compile action**.

Цель 2× не достигнута. Оставшийся потенциал требует существенно более
инвазивного изменения API/layout основных структур SchemeShard либо интерфейсов
сгенерированных protobuf-классов, что выходит за заданные ограничения.

## Методика измерений

Использовалась сборка `relwithdebinfo` на одной машине с одинаковым уровнем
параллелизма (48 компиляторов).

Для каждого запуска:

1. Во все исходные `.cpp` выбранного набора добавлялся уникальный безвредный
   комментарий, чтобы инвалидировать ровно C++ compile actions без применения
   force rebuild.
2. Запускалась сборка с `--show-timings`, `--stat` и отключённым remote store.
3. Из `longest-tasks.json` извлекались все действия типа `CC`.
4. Измерительный комментарий удалялся сразу после запуска.

Baseline и оптимизированное дерево запускались поочерёдно. Для итогового
сравнения использована медиана трёх запусков каждой версии.

## Основные изменения

### Разгрузка `schemeshard_impl.h`

Из `schemeshard_impl.h` удалены полные заголовки ряда подсистем, которые раньше
транзитивно разбирались почти каждым `.cpp` SchemeShard:

- DataShard;
- PersQueue;
- SchemeBoard;
- SequenceShard;
- Console;
- Kesus;
- Replication;
- BlobDepot;
- BlockStore и FileStore events;
- ColumnShard events;
- OLAP background tasks manager.

Вместо них добавлены точные forward declarations событий и совместимые alias'ы
для `TEventHandle`. Полные заголовки теперь подключаются непосредственно в тех
`.cpp`, где требуется тело события.

### Выделение `TSubDomainInfo`

Тяжёлое определение `TSubDomainInfo` больше не разбирается автоматически при
каждом включении `schemeshard_impl.h`.

`schemeshard_info_types.h` поддерживает облегчённый режим с forward declaration,
а файлы, которым действительно нужны методы или layout `TSubDomainInfo`,
подключают полное определение явно.

Для возможности работать с incomplete type:

- деструктор `TSchemeShard` перенесён из заголовка в `.cpp`;
- конструктор и деструктор `TMemoryChanges` перенесены в `.cpp`;
- сигнатуры с указателями на `TSubDomainInfo` сохранены без изменения типов.

### События ModifyScheme

Определения ModifyScheme-событий вынесены из большого `schemeshard.h` в новый
узкий заголовок `schemeshard_modify_scheme.h`.

Методы `AddWarning` и `AddNotice`, которым не требуется быть inline, перенесены
в `schemeshard.cpp`.

### Operation context и ACL

`schemeshard__operation_part.h` больше не включает полные реализации
`TMemoryChanges` и `TStorageChanges`. Он хранит только ссылки на предварительно
объявленные типы. Реальные потребители подключают соответствующие заголовки
явно.

Для операции изменения ACL добавлен узкий фасад
`schemeshard__operation_helpers.h`. Реализация фасада находится в
`schemeshard__operation_common.cpp`, где уже доступен полный `TSchemeShard`.

Отдельный файл `schemeshard__operation_modify_acl.cpp` после этого изменения
ускорился приблизительно с 34.2 до 10.9 секунды, то есть примерно в **3.14×**.

### OLAP manager

`TTablesStorage` вынесен из полного `olap/manager/manager.h` в отдельный
`olap/manager/tables_storage.h`.

Новый заголовок использует forward declaration `TColumnTableInfo`; полные
определения таблиц и store подключаются только в реализациях, которые обращаются
к их полям и методам.

### Inline-реализации

Ряд методов, из-за которых заголовкам требовался полный `TSchemeShard` или
тяжёлые protobuf-типы, перенесён в `.cpp`. Публичные сигнатуры и используемые
типы при этом не менялись.

### Исправление внешних транзитивных зависимостей

Полная сборка `ydbd` обнаружила несколько файлов в подтаргетах `index`, OLAP и
`sys_view/show_create`, которые неявно зависели от заголовков, ранее приходивших
через SchemeShard.

Им добавлены прямые include для:

- `TMemoryChanges` и `TStorageChanges`;
- `TSubDomainInfo`;
- `TColumnTableInfo` и `TOlapStoreInfo`;
- OLAP background sessions manager;
- `JoinPath`, Arrow `TimeUnit` и protobuf `TConstructor`.

Логика этих файлов не менялась.

## Проверенные и отменённые гипотезы

Следующие варианты не дали воспроизводимого улучшения либо ухудшили результат и
поэтому не были сохранены:

- отдельное дальнейшее разделение `operation_part`;
- удаление полного Hive-заголовка;
- условное исключение export/import типов;
- условное исключение вспомогательных object types;
- разделение timer actor;
- дополнительное удаление include из `schemeshard_info_types.h`;
- условное исключение отдельных protobuf-заголовков из блока subdomain;
- forward declaration SchemeCache, SysView и TxAllocator event containers.

Последние три семейства событий оформлены как контейнерные структуры с
вложенными типами, поэтому их нельзя корректно forward-declare без изменения
публичного API.

## Почему не получилось 2×

После сохранённых оптимизаций основная стоимость остаётся в нескольких тесно
связанных слоях:

1. `TSchemeShard` хранит много объектов по значению. Для таких полей C++ требует
   полные определения типов непосредственно в `schemeshard_impl.h`.
2. `schemeshard_info_types.h` остаётся крупным агрегатом структур с большим
   числом protobuf-полей и взаимных зависимостей.
3. `flat_scheme_op.pb.h`, config protobuf и связанные схемные protobuf-типы
   действительно используются во многих структурах по значению.
4. Часть event API использует вложенные `TPtr` в контейнерных классах, что не
   позволяет заменить include простым forward declaration.

Дальнейшее заметное сокращение потребовало бы как минимум одного из следующего:

- изменения layout `TSchemeShard` через pimpl/heap allocation;
- изменения публичных event API;
- разделения или изменения сгенерированных protobuf API;
- изменения ABI ряда структур.

Эти варианты противоречат требованиям сохранить текущие API/ABI и protobuf wire
format либо несут несоразмерный риск для такого рефакторинга.

## Совместимость

- Язык и система сборки не менялись.
- PCH не использовался.
- Сгенерированные protobuf-файлы не редактировались.
- Protobuf wire format не менялся.
- Публичные типы, enum values и сигнатуры сохранены.
- Пользовательских изменений до начала работы в worktree не было; все текущие
  изменения относятся к этой оптимизации.

Итоговый diff содержит 177 изменённых и 3 новых файла. Большинство правок в
`.cpp` — добавление прямых include вместо прежних транзитивных зависимостей.
