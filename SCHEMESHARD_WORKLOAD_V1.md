# SchemeShard workload: первая версия

`ydb workload scheme` нагружает схемные операции через публичные SDK API.
Поддерживаются строковые таблицы и топики: CREATE, ALTER, DESCRIBE; для каталога — LIST.

## Поведение

- `init` — необязательная подготовка: создаёт `initial_count` пустых объектов каждого типа независимо от набора операций `run`; существующие объекты считаются ошибкой.
- `initial_count` задаётся только в YAML, по умолчанию равен `count`, допустимы значения от 0 до `count`. При нулевых значениях `init` готовит только каталог.
- `count` — целевое общее число объектов типа, включая существующие. `run` проверяет фактическое наличие и схемы объектов, затем начинает нагрузку.
- CREATE достраивает недостающие объекты до `count`; после каждого успешного CREATE объект сразу доступен для ALTER и DESCRIBE.
- После достижения `count` CREATE прекращается. Остальные выбранные операции продолжаются до `--seconds`; запуск только с CREATE завершается при достижении цели.
- ALTER таблицы чередует добавление и удаление nullable-колонок `extra_<i> Utf8`; ALTER топика — consumers `reader_<i>`.
- `tables.alter_batch_size` и `topics.alter_batch_size` — размеры набора в одном ALTER, оба по умолчанию 1. Настройка доступна только в YAML.
- CREATE создаёт один объект, DESCRIBE описывает один объект, LIST читает содержимое одного каталога. Для них `*_batch_size` нет.
- Таблицы создаются с `id Uint64 NOT NULL` и ключом `(id)`, топики — без consumers; `alter_batch_size` не меняет начальную схему.
- DESCRIBE вызывает DescribeTable с границами партиций либо DescribeTopic; LIST вызывает ListDirectory для `path`.
- На одном объекте одновременно выполняется максимум одна операция, включая DESCRIBE. LIST выполняется независимо от операций над объектами.
- Без CREATE команда `run` ничего не создаёт: отсутствие каталога или нужных объектов — ошибка. Запуск только с LIST требует существующий каталог, группы объектов не обязательны и их схемы не проверяются.
- `--seconds` / `-s` — длительность нагрузки после проверки схем, по умолчанию 60; только для `run`. По истечении времени новые операции не планируются, начатые ожидаются.
- `--threads` / `-t` — размер пула рабочих потоков для обеих команд: от 1 до 256, по умолчанию 10. Вызовы SDK асинхронные, поэтому незавершённых операций может быть больше, чем потоков.
- Выводятся успешные операции отдельно по видам и общее время, включая подготовку и ожидание завершения. Подготовительные запросы не входят в счётчики нагрузки.

## YAML

```yaml
path: scheme_load_001
operations:
  create: 16
  alter: 16
  describe: 32
  list: 1
tables:
  count: 100
  initial_count: 20
  partitions: 16
  alter_batch_size: 8
topics:
  count: 50
  initial_count: 10
  partitions: 8
  alter_batch_size: 4
```

`path` — каталог относительно database; имена объектов — `table_0`, `topic_0` и далее внутри него.
`partitions` задаёт начальные партиции; автопартиционирование отключено. В YAML `count` и `partitions` обязательны для каждой указанной группы и положительны; `alter_batch_size` также положителен.
Значения `operations` — положительные лимиты незавершённых операций, общие для таблиц и топиков; сумма не больше 256. Это не веса и не частоты запросов. Отсутствующие операции выключены; пустой набор запрещён.
Без блока `operations` включены CREATE и ALTER с лимитом 1 каждый; старые `create_concurrency` и `alter_concurrency` поддерживаются, но их нельзя совмещать с `operations` в YAML.
Для `init` используется лимит CREATE, а если CREATE не выбран — 1. В примере `init` создаёт 20 таблиц и 10 топиков; `run` достраивает ещё 80 и 40, одновременно выполняя остальные операции.

## CLI и приоритет настроек

`--config` необязателен. Явные CLI-опции перекрывают YAML; отсутствующие опции сохраняют значения из файла.
`--path` меняет каталог; `--tables N` и `--topics N` меняют только `count` соответствующей группы, сохраняя остальные поля. Для новой группы партиции и размер ALTER по умолчанию равны 1.
`--partitions N` меняет партиции всех указанных групп. Если после переопределения `initial_count > count`, конфигурация отклоняется.
`--operations create=16,describe=32` полностью заменяет набор операций и их лимиты, включая старые поля concurrency. Поэтому `--operations describe=32` выключает CREATE и ALTER из YAML.
Без файла нужны `--path` и хотя бы одна из `--tables` / `--topics`; для LIST-only достаточно `--path`. Разные партиции для типов, `initial_count` и `alter_batch_size` доступны только в YAML; потоки и длительность — только через CLI.

```bash
ydb -e "$YDB_ENDPOINT" -d "$YDB_DATABASE" workload scheme run --config scheme.yaml --threads 10 --seconds 60
ydb -e "$YDB_ENDPOINT" -d "$YDB_DATABASE" workload scheme run --path scheme_load_002 --tables 100 --topics 50 --partitions 16 --operations create=16,alter=16,describe=32,list=1
```

Несовместимые схемы отклоняются до нагрузки. Ошибки останавливают выдачу новых операций; неоднозначные результаты DDL автоматически не повторяются. Метрики памяти и подтверждение OOM собираются отдельно на сервере.
