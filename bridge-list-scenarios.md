# ydb admin cluster bridge list: от обзора к подробностям

Основной пример: две базы по четыре группы, две piles. Таблицы показаны для широкого терминала.

## 1. Состояние piles

```text
$ ydb admin cluster bridge list
Pile dc1: PRIMARY
Pile dc2: NOT_SYNCHRONIZED
Generation: 42
```

Добавить счётчики синхронизации:

```text
$ ydb admin cluster bridge list --detailed
┌──────┬──────────────────┬───────────────┬────────────────┬────────────────┬────────────────┬──────────────────────┐
│ Pile │ State            │ Synced groups │ Syncing groups │ Pending groups │ Unknown groups │ Synced system groups │
├──────┼──────────────────┼───────────────┼────────────────┼────────────────┼────────────────┼──────────────────────┤
│ dc1  │ PRIMARY          │ 8/8           │ 0              │ 0              │ 0              │ 1/1                  │
│ dc2  │ NOT_SYNCHRONIZED │ 6/8           │ 1              │ 1              │ 0              │ 1/1                  │
└──────┴──────────────────┴───────────────┴────────────────┴────────────────┴────────────────┴──────────────────────┘
Generation: 42
```

В `dc2` одна группа синхронизируется, ещё одна ожидает. `Synced groups` считает группы баз; `Synced system groups` — системные группы отдельно.

## 2. Базы: список → фильтры → подробности

**Все базы, по строке на каждую pile:**

```text
$ ydb admin cluster bridge list --databases
┌───────────┬───────────────┬─────────┬──────┬─────────┬───────────────┐
│ Database  │ Pools         │ Mode    │ Pile │ Sync    │ Synced groups │
├───────────┼───────────────┼─────────┼──────┼─────────┼───────────────┤
│ /Root/db1 │ /Root/db1:ssd │ bridged │ dc1  │ SYNCED  │ 4/4           │
│ /Root/db1 │ /Root/db1:ssd │ bridged │ dc2  │ SYNCING │ 2/4           │
│ /Root/db2 │ /Root/db2:ssd │ bridged │ dc1  │ SYNCED  │ 4/4           │
│ /Root/db2 │ /Root/db2:ssd │ bridged │ dc2  │ SYNCED  │ 4/4           │
└───────────┴───────────────┴─────────┴──────┴─────────┴───────────────┘
```

**Оставить только отстающие базы в `dc2`:**

```text
$ ydb admin cluster bridge list --databases --pile dc2 --not-synced

├───────────┼───────────────┼─────────┼──────┼─────────┼───────────────┤

```

**Добавить подробности к той же выборке:**

```text
$ ydb admin cluster bridge list --databases --pile dc2 --not-synced --detailed
┌───────────┬───────────────┬─────────┬──────┬─────────┬───────────────┬────────────────┬────────────────┬────────────────┬─────────────────┬─────────────────────────────┐

│ /Root/db1 │ /Root/db1:ssd │ bridged │ dc2  │ SYNCING │ 2/4           │ 1              │ 1              │ 0              │ read timeout    │ 2026-11-03T10:00:00.000000Z │
```

`ydb admin cluster bridge list --databases --path /Root/db1` выбирает конкретную базу. Это фильтр вывода; база подключения не меняется.

## 3. Группы: список → фильтры → подробности

**Все группы найденной базы:**

```text
$ ydb admin cluster bridge list --groups --path /Root/db1
Database: /Root/db1
┌────────────┬───────────────┬──────┬─────────┐
│ Group      │ Pool          │ Pile │ Sync    │
├────────────┼───────────────┼──────┼─────────┤
│ 2181038081 │ /Root/db1:ssd │ dc1  │ SYNCED  │
│ 2181038081 │ /Root/db1:ssd │ dc2  │ SYNCED  │
│ 2181038082 │ /Root/db1:ssd │ dc1  │ SYNCED  │
│ 2181038082 │ /Root/db1:ssd │ dc2  │ SYNCED  │
│ 2181038083 │ /Root/db1:ssd │ dc1  │ SYNCED  │
│ 2181038083 │ /Root/db1:ssd │ dc2  │ SYNCING │
│ 2181038084 │ /Root/db1:ssd │ dc1  │ SYNCED  │
│ 2181038084 │ /Root/db1:ssd │ dc2  │ PENDING │
└────────────┴───────────────┴──────┴─────────┘
```

Один `Group` повторяется для разных piles. Для списка групп обязательно выбрать базу или пул.

**Оставить только несинхронизированные группы в `dc2`:**

```text
$ ydb admin cluster bridge list --groups --path /Root/db1 --pile dc2 --not-synced
Database: /Root/db1
┌────────────┬───────────────┬──────┬─────────┐
│ Group      │ Pool          │ Pile │ Sync    │
├────────────┼───────────────┼──────┼─────────┤
│ 2181038083 │ /Root/db1:ssd │ dc2  │ SYNCING │
│ 2181038084 │ /Root/db1:ssd │ dc2  │ PENDING │
└────────────┴───────────────┴──────┴─────────┘
```

**Добавить физические ID, этап и последнюю ошибку:**

```text
$ ydb admin cluster bridge list --groups --path /Root/db1 --pile dc2 --not-synced --detailed
Database: /Root/db1
┌────────────┬───────────────┬──────┬─────────┬────────────────┬───────┬─────────────────┬─────────────────────────────┐
│ Group      │ Pool          │ Pile │ Sync    │ Physical group │ Phase │ Last sync error │ Last error time             │
├────────────┼───────────────┼──────┼─────────┼────────────────┼───────┼─────────────────┼─────────────────────────────┤
│ 2181038083 │ /Root/db1:ssd │ dc2  │ SYNCING │ 2197815299     │ DATA  │ read timeout    │ 2026-11-03T10:00:00.000000Z │
│ 2181038084 │ /Root/db1:ssd │ dc2  │ PENDING │ —              │       │                 │ —                           │
└────────────┴───────────────┴──────┴─────────┴────────────────┴───────┴─────────────────┴─────────────────────────────┘
```

`Phase` — зафиксированный этап; `DATA` — перенос данных. Текущую активность показывает `Sync`. Последняя ошибка может оставаться при повторной попытке.

Вместо базы можно выбрать `--pool NAME` или точный `--pool-id BOX:POOL`.

## 4. Особые случаи

- **Ordinary:** `Mode: ordinary`, `Sync: N/A` — bridge-синхронизация не требуется.
- **Mixed:** счётчики относятся только к bridge-пулам базы.
- **Serverless:** выводится `Shared storage: /Root/shared` и состояние общего хранилища.
- **Имя pile:** `—` означает отсутствие привязки, `""` — пустое имя. Фильтр `--pile` исключает строки без привязки.

**Статусы и ошибки:**

- `PENDING` — синхронизация нужна, но пока не выполняется; `N/A` — не требуется.
- `UNKNOWN` — данных недостаточно. `--not-synced` включает `SYNCING`, `PENDING` и `UNKNOWN`.
- Нет подходящих строк — пустая таблица.
- При недоступности диагностики BSC `ydb admin cluster bridge list --detailed` сохраняет базовые состояния piles, пишет причину в stderr и возвращает ненулевой код. Списки баз и групп завершаются ошибкой без частичного вывода.

**Большие списки:** возвращаются целиком, без страниц и токенов. Фильтры позволяют оставить только отстающие группы даже при десятках тысяч групп в базе. При превышении лимита размера ответа или объёма обхода — ошибка с предложением сузить выборку, без усечения.

Готовность pile определяется её `State`; одного счётчика групп для этого недостаточно.
