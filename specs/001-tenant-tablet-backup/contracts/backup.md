# Backup compatibility contract

Добавляется административная POST-команда monitoring Hive; формат backup не меняется.

- Настроенный system_tablet_backup_config распространяется также на поддерживаемые системные
  таблетки тенантов. Оператор обеспечивает filesystem path на узлах размещения.
- ExcludeTabletIds продолжает исключать конкретные ID.
- Без backend файлы не создаются.
- Поддерживаемые типы и режим Normal перечислены в spec.md; пользовательские типы не включаются.
- Форматы snapshot/changelog/manifest и существующий reader остаются совместимыми.
- Доставку файлов на узел восстановления обеспечивает оператор; восстановление целого тенанта вне области задачи.

## Управление восстановлением

POST `/tablets/app?TabletID=<управляющий Hive>&page=SetRecoveryMode&tablet=<ID>&recovery=1`
сохраняет режим и перезапускает выбранную таблетку. `recovery=0` явно возвращает обычный запуск.
Ответ подтверждает сохранение настройки; готовность актора и результат восстановления проверяются
отдельно. Повтор того же значения не перезапускает таблетку.

Недопустимы GET, отсутствующий/неправильный recovery, неизвестный ID, неподдерживаемый тип,
external/locked/мигрирующая или остановленная таблетка. Сохраняются существующие права доступа monitoring.
Hive должен быть доступен вместе с каналами выбранной таблетки. Local без SupportsRecovery
не получает recovery boot. Для применения используется существующая форма RecoveryShard
`restoreBackup` с путём на узле запуска; после ошибки автоматического normal boot нет.
Нельзя понижать версию Hive, пока есть таблетки в recovery. Перезапуск recovery-актора требует
повторной проверки результата; успех предыдущего экземпляра не считается подтверждением текущего.
