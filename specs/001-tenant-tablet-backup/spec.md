# Feature Specification: Бекап тенантных системных таблеток

**Feature Directory**: `specs/001-tenant-tablet-backup`

**Created**: 2026-10-05

**Status**: Implemented; validated with unit/actor-runtime tests on 2026-10-06

**Input**: «Задача – поддержать бекап системных таблеток для тенантных системных таблеток»

## Clarifications

### Session 2026-10-05

- Q: Использовать существующую настройку бекапа или отдельный переключатель? → A: Пользователь подтвердил существующую настройку.
- Уточнение пользователя: задача включает не только создание бекапов, но и восстановление тенантных системных таблеток. Проверка reader/recovery-актора в изоляции недостаточна.
- Q: Выбранная таблетка существующего тенанта или все системные таблетки потерянного тенанта? → A: Выбранная таблетка, прежний TabletID.
- Q: Кто возвращает восстановленную таблетку в обычный режим? → A: Оператор явной командой после проверки результата.
- Q: Как оператор включает восстановление? → A: Через Hive по TabletID, без ручного переноса каналов хранения в bootstrap-конфигурацию.

## User Scenarios & Testing

### User Story 1 - Сохранение состояния системных таблеток тенанта (Priority: P1)

Администратор с настроенным бекапом системных таблеток получает бекапы также для системных
таблеток тенантов, чтобы иметь копию их состояния при потере основного хранилища.

**Why this priority**: Принадлежность тенанту сейчас исключает эти таблетки из бекапа.

**Independent Test**: Для тенантной системной таблетки получить снимок и последующие изменения,
прочитать их существующим средством восстановления и сравнить сохранённое состояние.

**Acceptance Scenarios**:

1. **Given** настроен бекап и системная таблетка принадлежит тенанту, **When** таблетка
   запускается в обычном режиме, **Then** создаются снимок и журнал последующих изменений.
2. **Given** завершён снимок и зафиксированы последующие изменения, **When** их читают для
   восстановления, **Then** восстанавливаются исходные данные с этими изменениями.
3. **Given** две таблетки одного системного типа, **When** сохраняются их бекапы,
   **Then** данные разных таблеток хранятся раздельно.

### User Story 2 - Сохранение ограничений бекапа (Priority: P1)

Администратор сохраняет действующие правила выбора таблеток и исключений при расширении охвата.

**Why this priority**: Расширение не должно включать пользовательские таблетки или нарушать восстановление.

**Independent Test**: Проверить допустимость бекапа для системных и пользовательских типов,
обычного и специальных режимов запуска, с принадлежностью тенанту и без неё.

**Acceptance Scenarios**:

1. **Given** пользовательская таблетка, **When** настроен системный бекап,
   **Then** принадлежность тенанту не включает для неё этот бекап.
2. **Given** системная таблетка запущена в режиме восстановления или другом специальном режиме,
   **When** выполняется работа таблетки, **Then** новый бекап не начинается.
3. **Given** ID тенантной системной таблетки внесён в исключения, **When** она запускается,
   **Then** её бекап не создаётся.
4. **Given** хранилище бекапов не настроено, **When** тенантная системная таблетка работает,
   **Then** бекап не создаётся.
5. **Given** системная таблетка без тенанта, **When** настроен бекап,
   **Then** сохраняется прежнее поведение.

### User Story 3 - Эксплуатационное восстановление тенантной системной таблетки (Priority: P1)

Оператор восстанавливает тенантную системную таблетку из созданного бекапа и возвращает её
в обычную работу через поддерживаемый механизм запуска таблеток.

**Why this priority**: Бекап должен быть применим при аварии; прямое создание recovery-актора
в тестовом окружении не подтверждает доступность этой операции оператору.

**Independent Test**: Восстановить настоящую тенантную системную таблетку через поддерживаемый
путь запуска и проверить её работу после возврата в обычный режим.

**Acceptance Scenarios**:

1. **Given** создан бекап тенантной системной таблетки, **When** оператор выполняет процедуру
   восстановления, **Then** восстанавливается сохранённое состояние и таблетка возвращается
   к выполнению своей системной функции после явного возврата оператором.
2. **Given** включён режим восстановления, **When** перезапускается управляющий Hive,
   **Then** режим сохраняется и обычные экземпляры таблетки не запускаются.
3. **Given** восстановление завершилось успехом или ошибкой, **When** оператор не давал
   команду возврата, **Then** таблетка остаётся в режиме восстановления.
4. **Given** включён режим восстановления, **When** Hive выбирает узел или запускает followers,
   **Then** recovery запускается только на поддерживающем его узле, а обычные followers не запускаются.
5. **Given** оператор повторяет команду с уже выбранным режимом, **When** Hive обрабатывает её,
   **Then** повторная команда не перезапускает таблетку и не сбрасывает результат восстановления.

Сценарий: восстановление выбранной системной таблетки существующего тенанта с прежним TabletID.
Восстановление всего потерянного тенанта в эту задачу не входит.

### Edge Cases

- Перезапуск таблетки сохраняет разделение бекапов по поколениям и существующие правила хранения.
- Ошибки записи обрабатываются существующей политикой повторов или перезапуска.
- Исключения таблиц и колонок продолжают действовать.
- Управляющий Hive и метаданные выбранной таблетки доступны; потеря этих метаданных не покрывается.
- В режиме восстановления обычные followers остановлены. Узлы без поддержки этого режима
  не должны запускать восстанавливаемую таблетку в обычном режиме.
- Смена узла использует настроенное на новом узле хранилище; перенос файлов между узлами не добавляется.

## Requirements

### Functional Requirements

- **FR-001**: Принадлежность тенанту MUST NOT препятствовать бекапу поддерживаемого системного типа.
- **FR-002**: Список поддерживаемых типов MUST сохраняться: Mediator, Coordinator, Hive,
  BSController, SchemeShard, Cms, NodeBroker, TxAllocator, Console.
- **FR-003**: Бекап MUST работать только при обычном запуске таблетки и настроенном хранилище.
- **FR-004**: Исключения по ID таблетки, таблицам и колонкам MUST сохранять прежнюю семантику.
- **FR-005**: Бекап тенантной таблетки MUST содержать снимок и последующие изменения,
  пригодные для чтения существующим механизмом восстановления.
- **FR-006**: Бекапы разных таблеток MUST быть разделены; действующие форматы, правила ротации,
  повторы и поведение нетенантных таблеток MUST сохраняться.

- **FR-007**: Система MUST обеспечивать эксплуатационный путь восстановления тенантных
  системных таблеток из созданных бекапов, включая запуск восстановления и возврат в обычную работу.
  Восстанавливается выбранная таблетка существующего тенанта с прежним TabletID.
- **FR-008**: После успешного восстановления таблетка MUST оставаться в режиме восстановления
  до явного возврата оператором в обычный режим. Ошибка восстановления MUST NOT приводить
  к автоматическому возврату в обычный режим.
- **FR-009**: Оператор MUST включать и выключать режим восстановления через управляющий Hive
  по TabletID, без ручного переноса каналов хранения. Hive MUST сохранять выбранный режим при
  своём перезапуске и повторном размещении таблетки. Обычные followers MUST NOT запускаться
  во время восстановления.

### Key Entities

- **Системная таблетка**: ID, тип, принадлежность тенанту и режим запуска.
- **Бекап таблетки**: снимок состояния и журнал изменений, связанные с ID и поколением таблетки.
- **Настройка бекапа**: хранилище, исключения, политика ошибок и хранения.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Все перечисленные поддерживаемые типы допускают бекап независимо от принадлежности тенанту.
- **SC-002**: Для проверяемой тенантной таблетки восстановленное состояние совпадает со снимком
  с применёнными последующими изменениями.
- **SC-003**: Во всех проверках неподдерживаемых типов и специальных режимов бекап запрещён.
- **SC-004**: Проверки исключённого ID, отсутствующего хранилища и прежнего нетенантного сценария проходят.

- **SC-005**: В согласованном аварийном сценарии оператор восстанавливает настоящую тенантную
  системную таблетку, после чего она выполняет свою системную функцию с восстановленным состоянием.

## Assumptions

- Используется существующая настройка системного бекапа без отдельного переключателя для тенантов.
  Подтверждено пользователем 2026-10-05: «Включить при существующей настройке».
- Восстановление всего потерянного тенанта вне области задачи: пользователь выбрал восстановление отдельной таблетки с прежним TabletID. Новые типы таблеток и новые хранилища не добавляются.
- На узле размещения таблетки оператор заранее настраивает доступное хранилище бекапов.
- Производительность и политика хранения остаются в рамках существующего механизма;
  отдельные нагрузочные цели пользователь не задавал.
