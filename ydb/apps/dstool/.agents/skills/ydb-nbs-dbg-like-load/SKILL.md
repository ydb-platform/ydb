# NbsDbgLike load automation

1. Read ydb/docs/en/core/contributor/load-actors-nbs-dbg-like.md for flag meanings, command recipes, and deployment requirements. Use dedicated load tablets and an explicit database and gRPC endpoint. Select the coordinator with `--node-id` when needed; a different gateway does not change a saved coordinator.
2. Run all actions under `ydb-dstool cluster workload nbs-dbg-like`. For a new workload, use `run` without `--tablet-id` or `--target`: dstool creates a dedicated tablet, runs the workload, and deletes the tablet after confirmed termination. Do not create or delete the tablet manually for this scenario. Pass allocation flags to `run` when needed: `--pool-name` selects both DDisk/PB pools, `--ddisk-pool-name` and `--pb-pool-name` override them separately, and repeated `--tablet-storage-pool` selects ordered tablet channels. Use `create` and `delete` only when an explicit tablet lifecycle is needed; use `run --tablet-id` or repeated `--target` for existing tablets. Each run or trial defaults to 10 seconds with zero warmup, 2048 inflight, and 65536 max inflight LSNs. Override inflight with `--inflight N` or `--inflight-from A --inflight-to B`; range values double each step, and `--trials` is 1 or an odd number. The CLI owns request construction, polling, checkpointing, retries, and median selection; do not reimplement them in shell loops.
3. Preserve the artifact directory printed to stderr. `run --no-wait` works for a single run on an explicit tablet and returns a handle; use `results --handle DIR --wait` to retrieve it. Handle-based results and stop save terminal replies and can read saved results offline. Resume interrupted work with `run --resume DIR`, without new run settings. Unknown/expired handles or a lost coordinator require investigation; never launch replacement work automatically. Automatic allocations are recorded in `auto.json` and retained when termination cannot be confirmed.
4. Check the execution state and the CLI verdict separately. Partial measured WritesErr or ReadsErr stays visible in every output format and passes the CLI verdict. A direction fails the measured-error check only when it has errors and zero successful measured operations (100% errors); `--allow-io-errors` relaxes that check. The flag does not excuse execution failure, cancellation, or an unresolved outcome. Histogram latencies are in microseconds; 64-bit tablet IDs and owner indices are JSON strings; node IDs are numbers.
5. Use `stop` for the saved run identity and wait for confirmed termination before starting another trial. Coordinator loss does not prove remote workers stopped. Completion covers client-request drain, not background flush/erase.
6. Serialize explicit create and delete for each Hive owner index, including across controllers and HTTP; reserve distinct indices across databases sharing a Hive. Concurrent lifecycle mutation is unsupported. Preflight checks do not make create atomic. After an ambiguous explicit create or delete, inspect Hive and the reported tablet ID before deciding whether to retry. Preserve local results. Same-coordinator overlap checks are not cluster-wide locks; do not reuse these tablets through another controller while a run may be active.

Implementation and validation: ydb/apps/dstool/lib/nbs_dbg_like_load.py owns the reusable workflow; ydb/apps/dstool/lib/dstool_cmd_cluster_workload_nbs_dbg_like.py exposes commands; ydb/apps/dstool/lib/ut/test_nbs_dbg_like_load.py tests recovery and verdicts. Follow the repository build rules for ydb/apps/dstool/lib/ut.
