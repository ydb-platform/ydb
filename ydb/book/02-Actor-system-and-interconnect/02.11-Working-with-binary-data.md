## 2.11 Работа с двоичными данными

В этом разделе рассмотрены основные контейнеры для работы с двоичными
данными и их передачи между акторами.

По историческим причинам самые старые части YDB для хранения двоичных
данных пользуются классом TString, который для этого никогда не был
предназначен, но прежде обладал хорошими свойствами. По сути, это был
ref-counted интрузивный указатель на буфер с данными, который можно было
безопасно передавать между потоками и небезопасно менять содержимое
этого буфера. Дальнейшее развитие TString в сторону std::string привело
к необходимости использовать особый тип, предназначенный для хранения
двоичных данных.

Контейнер TRcBuf специально предназначен для работы с двоичными данными.
Это указатель на буфер с refcount. Если создать из одного TRcBuf
несколько копий, то все они указывают на один и тот же буфер, который не
удалится, пока существует хотя бы один указатель. При аллокации буфера в
этом контейнере можно заранее организовать заданное количество свободных
байт перед данными и после них (headroom и tailroom). Это удобный
контейнер для подготовки данных и передачи результата подготовки одному
или нескольким потребителям. Счётчик ссылок --- атомарный, и это
позволяет одновременно пользоваться одним TRcBuf из нескольких потоков
или акторов.

По умолчанию предполагается, что содержимое буфера, разделяемого между
несколькими TRcBuf, остается тем же самым. Соответственно, при
необходимости изменить TRcBuf следует использовать метод Detach, когда
единственный владелец буфера получает указатель на начало буфера для
модификации данных. В случае же, если существует несколько
пользователей, владеющих буфером TRcBuf, вызов Detach приведёт к
созданию копии буфера, единственным владельцем которого будет экземпляр
TRcBuf, чей метод Detach был вызван. При этом указатель будет получен на
него.

Помимо этого, есть возможность получить прямой доступ к разделяемому
буферу с помощью Unsafe-функций. При модификации данных разделяемого
буфера изменится содержимое общего буфера, на которое продолжает
указывать множество TRcBuf.

TRope представляет собой последовательность фрагментов TRcBuf-буферов.
Он позволяет без копирования данных собрать составной буфер из фрагментов
одного или нескольких буферов. Interconnect поддерживает передачу
прикреплённых к сообщению фрагментов TRope без лишней сериализации
и копирования данных.

Важно: нет штатного способа положить TRcBuf в protobuf, их действительно
надо передавать, не сериализуя.

Есть ещё один владеющий тип --- TSharedData. Он более простой, чем
TRcBuf-тип, тоже с атомарным refcounter. TSharedData не имеет headroom и
tailroom, но поддерживает операцию Trim (отрезание куска в конце
буфера). Благодаря своей простоте TSharedData работает чуть быстрее, чем
TRcBuf.

TRcBuf умеет работать как обертка вокруг другого буфера, поддерживает
несколько типов буферов (собственный бэкенд, TString, TSharedData). Это
позволяет всем, кто умеет работать с TRcBuf, автоматически работать с
TSharedData, завернув его в TRcBuf. А вот наоборот --- не выйдет.
