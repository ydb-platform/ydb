## 4.2 Локальная база и транзакции

Локальная база --- удобный интерфейс к персистентно хранимому состоянию
таблетки. Поверх базовой таблетки работает так называемая локальная база. Она позволяет самой таблетке пользоваться хранилищем не
в терминах записи в лог, а в терминах работы с небольшими таблицами в
базе данных. Операции над этими таблицами выполняет код на C++ через
достаточно простое и удобное API.

Для commit redo по умолчанию действует лимит 256 MiB (`MaxCommitRedoMB`),
который можно изменить через Tablet Controls; допустимый диапазон значения
этой настройки --- от 1 до 4096 MiB. Кроме него, выполнение транзакции
ограничивается профилями памяти (`InitialTxMemory`, `TxMemoryLimit`,
`StaticTxMemoryLimit` и `StaticTabletTxMemoryLimit`), поэтому чтение также
может остановиться по лимиту памяти, а не только при исчерпании памяти узла.

Операции чтения выполняются быстро, особенно если данные попали в кэш.
Операции записи существенно медленнее.

Системные таблетки, как правило, всё держат в памяти и локальной базой
пользуются только для персистентного хранения. Обычно на старте
системная таблетка делает попытку предзагрузки: если все страницы оказались
в памяти, она загружается, а если чего-то в памяти не оказалось, система
ждёт, пока данные с диска догрузятся, и потом повторяет попытку.

При обращении к страницам исполнитель ведёт их учёт для транзакции:
доступные страницы закрепляются, а недостающие заносятся в список
для загрузки. После загрузки они также добавляются в набор закреплённых
страниц. Пока закрепление сохраняется, следующие вызовы `Execute`
могут использовать эти данные без повторного чтения из хранилища.
Так транзакция накапливает нужные ей страницы между попытками.

В транзакции полезно заранее заказать все данные, необходимые для
выполнения, чтобы сократить число повторов. При достаточной памяти
и неизменном наборе данных практический ориентир --- один повтор после
загрузки всех недостающих страниц. Если данные уже в памяти, повтор не нужен.
Этот подход особенно полезен для транзакций инициализации (`tx init`),
заранее загружающих нужные таблицы.

Дополнительные повторы могут потребоваться, если дальнейшие чтения
обнаружат новые страницы, между попытками изменятся данные или состав
SST после компакции. Кроме того, при ожидании увеличения выделенного
ресурса памяти исполнитель может снять закрепление страниц и освободить
связанные с транзакцией данные.
