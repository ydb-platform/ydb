## 5.6 Board

Board --- это сервис для публикации информации по ключу. В частности, у
нас он используется для дискавери. Используется специальный ключ, gRPC+
имя, и публикуется информация про gRPC-эндпойнт в виде протобуфа. Вся
эта информация хранится в акторах board, работающих на тех же нодах, где
и state storage. Board --- это распределённое in-memory key-value
хранилище. Любой, кто хочет сделать запрос, заранее знает ноды Board, на
которые нужно сходить, и получает с них список протобуфов по этому
ключу. Так как в основном это используется именно для дискавери,
запрашивающий получает списки gRPC-эндпойнтов, собирает все протобуфы
локально и получает список эндпойнтов для базы данных.

KQP публикует в Board информацию о ресурсах на ноде в виде протобуфа,
чтобы находить ноды своей базы и определять, какие вычисления на них
можно запускать.

Информация о тенантах публикуется в двух местах: в одном указывается,
что конкретный nodeId обслуживает определённого тенанта, а в другом
gRPC-proxy публикует информацию о том, что нода с заданными настройками
gRPC предоставляет указанный набор сервисов для данного тенанта.
Это необходимо для операции list endpoints.

Помимо дискавери, Board используется для публикации редко
меняющейся информации, которую необходимо собирать со всех нод.
Данные хранятся по произвольным ключам.

Для публикации данных на ноде запускается Board Publisher. Он отправляет
данные актора по заданному ключу выбранным репликам Board. Опубликовавший
данные считается их владельцем. Реплики хранят публикации и подписываются
на завершение interconnect-сессий с публикующими акторами. При завершении
такой сессии реплика удаляет связанные с ней публикации. Publisher
повторяет попытки публикации и после восстановления связи заново
публикует информацию.
