## 5.8 CMS

CMS (cluster management system) --- это системная таблетка. Задумывалась
как CMS для сервиса YDB. Для того чтобы обслуживать ноды YDB, необходимо
использовать сервис CMS, предоставляющий API, которое и использует
команда эксплуатации, чтобы выключать машины для их обслуживания
и ремонта.

Для реализации этого API CMS выставляет наружу специальный протокол общения. Также она умеет хранить разрешения, которые выдала
на обслуживание ноды, вовремя их обновлять, удалять и работать с ними.
CMS не выдаёт разрешения, если это приведёт к потере доступности
кластера.

Есть HTTP-API, вызовы которого может обрабатывать каждый инстанс сервера
YDB. Этот HTTP API конвертируется в API CMS, преобразуется в сообщение и
по пайпу идёт в таблетку CMS.

CMS периодически собирает информацию со всего кластера. То есть она
общается с whiteboard, с BS_Controller, с тенант-пулами и даже
локальными сервисами типа Name Service. CMS собирает информацию
про все ноды, все PDisk-и и VDisk-и, имеющиеся в кластере, и тенанты,
которые работают на динамических нодах. Из всего этого она строит
структуры и по ним определяет, когда можно выдавать разрешения на
операции, а когда нельзя.

CMS не только разрешает выключать машины для ремонта. Она используется и
для получения разрешения на перезапуск ноды для rolling restart. Эти
разрешения не конфликтуют: если машина выдана для rolling
restart, то она не будет выдана для обслуживания, и наоборот.

CMS записывает в лог решения о выдаче разрешений на обслуживание или
перезапуск нод и об отказах в таких разрешениях.

Внешняя система управления оборудованием обращается через API. Люди
используют другое API, оно тоже
HTTP. Также доступен gRPC CMS Public API.
