## 8.1 Язык YQL

### Что такое YQL и чем отличается от SQL

В качестве языка запросов в YDB используется YQL (YDB Query Language)
--- диалект SQL. По сути, это SQL с некоторыми дополнениями и
особенностями. Основные из них --- это строгая типизация, то есть каждое
выражение имеет изначально известный тип, и нативная поддержка составных
типов, то есть кроме основных типов, таких как строки, числа и datetime,
YQL нативно умеет работать с контейнерами (списки, структуры, словари,
кортежи). Он поддерживает именованные подзапросы, которые упрощают запись
вложенных запросов. Для всех параметров запросов явно указывается их
тип.

В язык добавлены некоторые DML-конструкции, специфичные для YDB.
UPSERT (update or insert) обновляет существующую строку или добавляет
новую, если строки с таким ключом нет. Эта операция,
нативная для YDB, очень эффективна. Replace --- одна из вариаций, когда
заменяются значения во всех колонках при обновлении. Updateon и deleteon
--- обновление и удаление строчек, но не по предикату, а по переданному
списку ключей (и, опционально, значений).

Запросы в целом выглядят понятно, и писать их может любой человек,
который ранее работал с SQL.

Можно говорить о том, что на вход поступают запрос и его параметры.
Параметры просто передаются как есть, а вот запрос может пройти по
одному из двух путей --- быстрый и медленный. Если запрос уже есть
в кэше скомпилированных запросов, исполнение идёт по быстрому пути. В противном
случае выполняется компиляция запроса. Компиляция требует дополнительных вычислений.
Практический ориентир для оценки этих затрат --- порядка 150 мс
даже для простого запроса. Фактическое время зависит от запроса,
используемой схемы данных, оборудования и нагрузки. Попадание в кэш
позволяет избежать повторной компиляции. Если для запроса запрошено
сохранение результата компиляции
и этот результат допускает кэширование, он может быть сохранён на сервере
для последующих выполнений.
