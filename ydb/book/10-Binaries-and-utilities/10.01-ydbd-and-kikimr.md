## 10.1 ydbd и kikimr

В этом разделе рассмотрены режимы работы и конфигурация исполняемого
файла сервера YDB.

Основным исполняемым файлом сервера YDB является `ydbd`. В старых версиях или в специфических контекстах можно встретить название `kikimr` (историческое название проекта), но сейчас стандартом является `ydbd`. Это единый бинарный файл («монолит»), который содержит код всех подсистем YDB: акторную систему, распределённое хранилище (BS_Controller, NodeWarden, PDisk, VDisk), таблеточную инфраструктуру и слой выполнения запросов.

### Режимы работы

Бинарный файл `ydbd` может работать в нескольких режимах, определяемых подкомандой при запуске.

#### Сервер

Основной режим работы. Команда `ydbd server` запускает процесс узла (ноды) кластера.
Узел может выполнять различные роли в зависимости от конфигурации:

*   **Storage Node**: хранит данные (запускает PDisk/VDisk).
*   **Compute Node** (или Dynamic Node): выполняет запросы и размещает таблетки, используя распределённое хранилище для надёжного хранения данных. На такой ноде работают, в частности, gRPC-прокси и Query Processor.
*   **Hybrid Node**: совмещает функции хранения и вычислений (типично для небольших кластеров).

Пример запуска динамической ноды в настроенном кластере:

```bash
ydbd server --log-level 3 --syslog --tcp \
  --node-broker localhost:2135 \
  --ic-port 19002 \
  --grpc-port 2136
```

Здесь `localhost:2135` --- доступная gRPC-точка входа для регистрации
через Node Broker, `19002` --- interconnect-порт запускаемой ноды,
а `2136` --- её gRPC-порт. Параметр `--ic-port` обязателен для показанного
способа регистрации динамической ноды. Адрес точки входа и порты
выбираются в соответствии с конфигурацией инсталляции.

#### Административные инструменты

`ydbd` также содержит встроенные инструменты для низкоуровневого администрирования, которые могут быть полезны при восстановлении кластера или отладке, когда API недоступен. Например, утилиты для прямой работы с дисками (PDisk) или локального просмотра структур данных.

### Конфигурация

Конфигурация `ydbd` слоистая и может быть статической или динамической.

1.  **Статическая конфигурация**: Файл (обычно YAML или Protobuf), передаваемый при старте процесса через флаг `--config` или `--yaml-config`. Содержит базовые параметры, необходимые для подключения к сети, интерконнекту и старта начальных компонентов (например, адрес Node Broker или статический список узлов).
2.  **Динамическая конфигурация**: Хранится внутри самого кластера (в таблетке Console). Узел при старте (или в процессе работы) получает актуальную конфигурацию от сервиса Console. Это позволяет менять настройки кластера «на лету» без перезапуска процессов (для поддерживаемых параметров).

Узлы могут быть помечены метками (`--label name=value`), которые используются в динамической конфигурации для применения настроек к группам узлов (например, «все узлы в дата-центре X» или «все compute-ноды»).

### kikimr как исторический артефакт

Имя `kikimr` всё ещё можно встретить:

*   В именах внутренних пространств имен C++ кода (namespace NKikimr).
*   В названиях некоторых системных путей или переменных окружения.
*   Как имя драйвера или утилиты в старых инсталляциях.

С точки зрения пользователя, `ydbd` — это современная «обертка» и точка входа в систему.
