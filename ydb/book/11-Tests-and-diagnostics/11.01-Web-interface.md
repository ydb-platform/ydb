## 11.1 Веб-интерфейс

По умолчанию на порт 8765 назначен веб-интерфейс ноды, через который
открывается Embedded UI.

Подробнее про Embedded UI можно посмотреть в документации.

Использовать Embedded UI в критических ситуациях следует с осторожностью,
так как отсутствие данных о проблемах в нём может быть вызвано не
отсутствием проблем, а некорректной работой самого Embedded UI. Рекомендуется
переходить по ссылке Developer UI в правом верхнем углу и пользоваться
другими страницами веб-интерфейса.

На каждой ноде есть локальный сервис --- whiteboard. Он легковесный и
простой, и все компоненты шлют туда сообщения с информацией про своё
состояние. Кроме того, есть набор классов, или вьюверный бэк, который
умеет особым образом собирать информацию со всех нод и объединять информацию. Там нужно обходить
хитрым образом потому, что некоторая информация распределена по нодам.
Например, информация о группах хранения: о ней могут рассказать разные
ноды. Или информация о таблетке: несколько нод сообщают, что видели эту
таблетку, но вьювер доверяет той, на которой поколение больше. Вьювер
занимается этим обходом и объединением информации.

Вся идея состоит в том, чтобы он мог работать при отказе любых компонент
системы. То есть даже если весь кластер придёт в неконсистентное состояние,
ничего не работает, но вьювер должен работать всегда. Даже если он не
все соберет, не про все покажет, но гарантированно покажет хотя бы то,
что смог собрать, --- кстати, в отличие от health check.

У них совершенно разные стратегии. Для health-check важен консистентный
ответ: рассказал BS_Controller про сторадж --- хорошо, не рассказал ---
жалуемся на него. Viewer использует другую стратегию: при недоступности BS_Controller он обращается к альтернативным источникам информации,
потому что необходимо
любой ценой собрать информацию.

Старый Viewer и Embedded UI по большей части используют одни и те же
механизмы. Принцип одинаковый, но в Embedded UI оптимально реализовано
получение информации, поэтому он может обновлять данные быстрее. Он показывает
только то, что сейчас на экране, и API улучшено, и UI может спрашивать
только про то, что ему сейчас требуется показать на экране.

Старый вьювер мог получить одним запросом большое количество данных,
что делало частое обновление невозможным. А Embedded UI
запрашивает постранично и получает маленькие JSON-документы.
