## 12.1 Запуск статической ноды

Запуск статической ноды происходит следующим образом: процесс
запускается с указанием номера ноды в качестве аргумента командной
строки. Считывается конфигурация из файла на ноде, затем создаются
сервисы и запускается акторная система и интерконнект.

Если в конфигурации есть описание PDisk и VDisk, находящихся на этой
ноде, Node Warden запускает эти PDisk и VDisk. Для всех описанных в
конфигурации групп запускаются DSProxy. Node Warden пытается установить
pipe к blob storage controller и получить конфигурацию динамических
групп.

Если в конфигурации есть таблетки, которые должны запускаться через
bootstrapper, соответствующие bootstrapper запускаются на ноде и
пытаются договориться с другими bootstrapper о том, кто запускает
таблетку, после чего bootstrapper может пытаться запустить таблетку.

Local пытается установить подключение к Hive, чтобы начать запускать
таблетки по его указанию.

Когда запускается и загружается blob storage controller, Node Warden
получает от него конфигурацию PDisk и VDisk и запускает все PDisk, VDisk
и DSProxy, конфигурацию которых получает.

При запуске таблеток они отправляют запросы в blob storage, при этом
если DSProxy этих групп ещё не сконфигурированы, запросы попадают в Node
Warden, а он пытается получить конфигурацию от blob storage controller.
Если конфигурацию не удаётся получить несколько секунд, Node Warden
пытается получить конфигурацию от других Node Warden, обращаясь по
очереди к Node Warden других нод. До получения конфигурации небольшое
количество запросов в группу держится в очереди недоконфигурированной
DSProxy, после чего либо будет получена конфигурация и установлена связь
через BSQueue с достаточным для выполнения запросов количеством VDisk,
либо может наступить таймаут или переполнение очереди, после чего на все
запросы из очереди отправляется ответ с ошибкой.

Локальная подсистема конфигурации получает динамическую конфигурацию
от Console и передаёт обновления подписанным сервисам.
