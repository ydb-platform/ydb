## 12.3 Поломка ноды

При выходе из строя ноды может произойти следующее:

- таблетки, запущенные на этой ноде, перестанут работать;
bootstrapper-ы на других нодах заново запустят управляемые ими таблетки;
Hive потеряет связь с local на сломавшейся ноде и перезапустит
управляемые им таблетки на других нодах;

- VDisk и PDisk, запущенные на этой ноде, перестанут работать. Это
заметят BS_Controller, CMS и Sentinel. Последний отправит в
BS_Controller команду смены статуса диска на INACTIVE и запустит отсчёт
1 часа (настраиваемо). По истечении этого времени он отправит в
BS_Controller команду смены статуса диска на FAULTY. Self-Heal в
BS_Controller попытается переназначить VDisk на FAULTY PDisk-ах на
другие PDisk-и. В случае успеха будут запущены новые VDisk-и и начнётся
синхронизация индексов этих VDisk-ов с остальными в группе, а затем
данные реплицируются на эти новые VDisk-и;

- реплики State Storage, Board и Scheme Board на этой ноде перестанут
работать. При включённых self-management и автоматическом восстановлении
State Storage в Sentinel сведения о состоянии нод используются
DistributedConfigKeeper для изменения размещения реплик. В Sentinel
этот механизм включается полем Enable в StateStorageSelfHealConfig;
по умолчанию оно выключено. Управление каждой подсистемой дополнительно
регулируется настройками AutomaticStateStorageManagement,
AutomaticStateStorageBoardManagement и AutomaticSchemeBoardManagement.
Для автоматического переноса реплик включают соответствующие
настройки;

- потеря связи с нодой обнаруживается по ошибке соединения либо
по механизму контроля его работоспособности. В обычном режиме
interconnect проверяет время с последнего приёма данных; тайм-аут
DeadPeer по умолчанию равен 10 секундам. В режиме kernel liveness
для обнаружения потери связи используются механизмы TCP ядра ОС.
При потере TCP-соединения interconnect может попытаться восстановить
его в пределах прежней сессии. Если сессия завершается, подписчики
получают уведомление о разрыве, а уведомления о недоставке сообщений
формируются с учётом их флагов. Время получения этих уведомлений
зависит от способа обнаружения потери связи, попыток восстановления
сессии и флагов сообщений. Для части уже отправленных запросов результат
выполнения может остаться неизвестным отправителю.
