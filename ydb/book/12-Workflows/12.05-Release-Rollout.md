## 12.5 Выкатка релиза с роллинг-рестартом

Когда выпускается новая версия YDB, кластеры обычно не останавливаются
для обновления. Новый релиз выкладывается с роллинг-рестартом без потери
работоспособности кластера.

Новую версию раскладывают на нодах вместо старой. При этом Linux
продолжает выполнять старую версию бинарника, хотя в файловой системе
вместо него уже подложен новый. Если на какой-либо ноде после этого
процесс YDB упадёт, например, из-за OOM, то перезапустится уже новая
версия.

Затем у CMS запрашивается разрешение на перезапуск нод YDB. CMS выдаёт
разрешения так, чтобы работоспособность кластера не была нарушена. Она
следит за тем, чтобы одновременно не перезапускалось слишком большое
количество нод, диски которых участвуют в группах распределённого
хранилища, или нод, которые участвуют в state storage, или же нод,
предназначенных для запуска системных таблеток.

Ноды, перезапуск которых разрешён CMS, перезапускаются. Постепенно
перезапущенными оказываются все ноды кластера, и после этого на них
работает уже новая версия YDB.
