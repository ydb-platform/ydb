# Идеи для обсуждения трассировки с DataShard

Локальная заметка для отдельного обсуждения; в текущий PR не входит.

## Разделение дерева по уровням

Можно согласовать общую политику: на Basic показывать крупные этапы запроса,
на Detailed раскрывать отдельные задачи и акторы. Это изменение видимости
спанов в общей трассе; отдельные конфиг, sampling и коллектор не нужны.
Численные значения общих уровней и уровни других компонентов менять не требуется.

Предложение для KQP в `ydb/library/wilson_ids/wilson.h`:

| Спаны | Сейчас, как в базе PR | Возможное изменение |
| --- | --- | --- |
| `DataExecuterRunTasks`, `ScanExecuterRunTasks` | Detailed | Basic |
| `KqpNodeSendTasks`, `KqpNodeCreateTasks`, `ComputeActor` | Basic | Detailed |
| `ReadActor`, `LookupActor`, `LockActor` | Basic | Detailed |
| `ForwardWriteActor`, `DirectWriteActor`, `BufferWriteActor` | Basic | Detailed |

Это настройки KQP. Для DataShard нужно отдельно выбрать операции, которые
останутся видны на его Basic, и внутренние шаги, которые будут раскрываться
на его Detailed/Diagnostic. У разных компонентов свои численные пороги;
нельзя автоматически переносить пороги KQP на DataShard.

При согласовании проверить совместное дерево KQP → DataShard для чтения,
записи и распределённого коммита: при скрытом промежуточном спане дочерние
спаны должны сохранять существующего родителя. Результат операции и основные
атрибуты должны оставаться доступны на видимом этапе.

В текущем KQP PR прежние назначения уровней в `wilson.h` восстановлены.
Новые спаны стадий KQP остаются на Detailed, чтения отдельных шардов —
на Diagnostic. Код и уровни DataShard не меняются.
