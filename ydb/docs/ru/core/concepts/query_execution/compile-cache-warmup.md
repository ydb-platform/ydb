# Прогрев кеша компиляции

Прогрев кеша компиляции подготавливает планы [популярных запросов](#query-selection) при запуске [ноды базы данных](../glossary.md#database-node). Нода получает тексты запросов из кешей других нод той же базы данных и компилирует их локально. Это сокращает задержки первых запросов после перезапуска или добавления ноды.

{{ ydb-short-name }} хранит скомпилированные планы запросов в памяти нод. Повторное использование плана позволяет обслужить запрос без новой компиляции. При перезапуске ноды её кеш теряется. Во время прогрева запросы подготавливаются, но не выполняются и не изменяют данные базы.

## Как проходит прогрев

1. Нода обнаруживает ноды той же базы данных и читает их кеши через системное представление [`.sys/compile_cache_queries`](../../dev/system-views.md#compile-cache-queries).
2. Из полученных записей выбираются наиболее часто используемые запросы. Количество запрашиваемых нод, выбранных запросов и одновременно выполняющихся компиляций ограничено [настройками прогрева](../../reference/configuration/table_service_config.md#compile-cache-warmup).
3. Выбранные запросы компилируются с учётом пользователя, типа запроса, синтаксиса и типов параметров. Готовые планы сохраняются в локальном кеше.
4. После завершения прогрева нода появляется в списке доступных [эндпоинтов](../connect.md#endpoint) базы данных и начинает обслуживать клиентские запросы. До этого прямое обращение к ноде может возвращать `UNAVAILABLE` с сообщением о прогреве кеша.

### Выбор запросов {#query-selection}

Для прогрева выбираются часто используемые запросы из кешей работающих нод. При отборе учитываются статистика обращений и время, необходимое для компиляции. Объём работы ограничен настройками прогрева, поэтому часть запросов может не попасть в выборку.

Прогрев поддерживает запросы через Table Service и Query Service, в том числе параметризованные запросы.

## Рестарты и ошибки

Прогрев полезен при последовательном перезапуске нод: работающие ноды сохраняют кеши и предоставляют запросы запускаемой ноде. В базе данных с одной нодой прогрев пропускается, поскольку нет других нод, из которых можно получить запросы.

Кеш не сохраняется на диске. После одновременного перезапуска всех нод прогрев может не найти запросов для подготовки. В этом случае кеш заполняется обычным образом при поступлении клиентских запросов.

Прогрев ограничен двумя сроками: после мягкого лимита новые компиляции не запускаются, а уже начатые могут завершиться; по достижении жёсткого лимита прогрев завершается. Ошибка получения кеша или компиляции отдельных запросов не блокирует запуск ноды навсегда. Уже подготовленные планы остаются в кеше и могут использоваться клиентами.

Прогрев не гарантирует, что каждый последующий запрос найдёт готовый план: запрос мог не попасть в выбранную часть кеша, не успеть скомпилироваться или отличаться по контексту выполнения. Планы также могут быть вытеснены из кеша или потребовать повторной компиляции после изменения схемы.

На системных нодах корневого домена прогрев не запускается. Для serverless-баз данных получение кеша через `.sys/compile_cache_queries` недоступно.
