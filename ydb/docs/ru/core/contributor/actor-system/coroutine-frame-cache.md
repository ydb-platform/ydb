# Кеш кадров корутин

Кеш кадров корутин — локальный для рабочего потока набор списков свободных блоков памяти, которые повторно используются для кадров корутин без собственного стека. Он сокращает накладные расходы на выделение памяти из кучи и не меняет правила владения кадрами, времени жизни актора, отмены и принудительного уничтожения; эти правила описаны в разделах [«Акторы на корутинах»](coroutine-actors.md) и [«Сбои и завершение работы»](failure-and-shutdown.md). Читайте эту страницу, если настраиваете лимит кеша, читаете его статистику или тестируете выделение памяти.

## Какие кадры используют кеш

Корутины актора верхнего уровня и все кадры `async<T>`, включая свободные функции, константные методы и лямбды-корутины, выделяют память через `TAsyncFrameCache::Allocate` и освобождают её через `TAsyncFrameCache::Free` с передачей размера. Компилятор может полностью устранить выделение памяти для корутины.

У каждого исполнительного потока пулов BASIC, IO и общих пулов есть один `TAllocationCache<TAsyncFrameCacheTag>`, общий для всех акторов, выполняющихся в этом потоке. Рабочий поток общего пула при переключении между пулами сохраняет тот же кеш. Вне исполнительного потока текущего кеша нет, и кадры выделяются из кучи.

## Классы размеров и лимит

Кеш хранит семь списков свободных блоков по принципу «последним пришёл — первым вышел» (LIFO) ёмкостью 1, 2, 4, 8, 16, 32 и 64 KiB:

- запрос до 1 KiB включительно использует список 1 KiB, а больший запрос до 64 KiB включительно — наименьший подходящий список;
- запрос свыше 64 KiB обслуживается напрямую из кучи и никогда не сохраняется в кеше;
- запрос до 64 KiB включительно округляется до ёмкости списка даже вне рабочего потока или при нулевом лимите, поэтому любой рабочий поток позже может сохранить такой блок.

Лимит ограничивает суммарную округлённую ёмкость свободных блоков, которые хранит один рабочий поток. Возвращаемый блок, который не помещается в оставшийся лимит, освобождается в кучу; отдельного ограничения на список нет. Лимит не учитывает активные кадры, метаданные кеша и служебные данные аллокатора, поэтому он не ограничивает общий объём памяти корутин. Для выделенной памяти сохраняется выравнивание `__STDCPP_DEFAULT_NEW_ALIGNMENT__`; повышенное выравнивание кадров корутин не поддерживается.

Кадр не хранит указатель на кеш, из которого он выделен. Освобождение с передачей размера возвращает блок в кеш освобождающего потока с учётом его лимита, а вне исполнительного потока — в кучу. Поэтому кадр можно освободить в другом рабочем потоке или при завершении работы без TLS актора. Когда исполнительный поток останавливается, его кеш отвязывается, и последующие освобождения в этом потоке возвращают память в кучу. Свободные блоки, сохранённые в кешах рабочих потоков, освобождаются только при уничтожении системы акторов; живые кадры кеш никогда не освобождает.

## Настройка лимита

Лимит по умолчанию — 4 MiB на рабочий поток (`TAsyncFrameCache::DefaultSizeBytes`). Значение `0` отключает сохранение блоков: кеш существует, но каждый возвращаемый блок освобождается в кучу. Чтобы задать другой лимит, зарегистрируйте подсистему `TAsyncFrameCache` в `TActorSystemSetup` до запуска системы акторов:

```cpp
setup->RegisterSubSystem(std::make_unique<TAsyncFrameCache>(8 * 1024 * 1024));
```

Если настройки не регистрируют эту подсистему, система акторов регистрирует её с лимитом по умолчанию. Для серверов {{ ydb-short-name }} значение `NKikimrConfig::TActorSystemConfig::AsyncFrameCacheSizeBytes` (по умолчанию `4194304`) передаётся в эту подсистему. Кеши рабочих потоков создаются при запуске системы акторов, поэтому новый лимит применяется только после перезапуска.

## Статистика

В исполнительном потоке вызов `TAllocationCache<TAsyncFrameCacheTag>::GetCurrent()->GetStats()` возвращает статистику кеша этого рабочего потока: `HeapAllocations` (промахи кеша, включая запросы свыше 64 KiB), `CachedBytes` (округлённая ёмкость свободных блоков), `CachedFrames` и `SizeClasses` (число непустых списков). Вызывайте его только в потоке-владельце. Измеряйте показатели в потоке, выполняющем нагрузку, и прогревайте кеш в том же потоке.

Для всей системы акторов вызов `actorSystem->GetSubSystem<TAllocationCacheSubSystem>()->GetCachedStats(TAsyncFrameCache::FamilyId())` возвращает суммарные `CachedFrames` и `CachedBytes`. После запуска системы акторов его можно вызывать из любого потока без блокировки, но он должен завершиться до уничтожения системы акторов.

Сумма учитывает каждый исполнительный поток этой системы акторов один раз, включая остановленные потоки до уничтожения системы акторов. В неё не входят активные кадры, другие системы акторов и кеши, привязанные в тестах. Рабочие потоки обновляют счётчики relaxed-загрузками и записями, поэтому сумма приблизительна, пока потоки выделяют или освобождают память, и точна, когда кеши не изменяются.

Сборщик статистики системы акторов публикует эту сумму один раз за цикл сбора, обычно каждую секунду, как показатели текущего значения без разбивки по потокам, пулам или классам размеров:

| Группа счётчиков | Показатели |
|---|---|
| `counters=utils/subsystem=async_frame_cache` | `CachedFrames`, `CachedBytes` |
| `counters=utils/subsystem=allocation_cache/family=AsyncFrames` | `CachedBlocks`, `CachedBytes` |

## Санитайзеры

Повторное использование блоков остаётся включённым в сборках с санитайзерами. Под AddressSanitizer (ASAN) свободные блоки полностью помечаются как недоступные, включая ссылку списка; кеш временно разрешает доступ к ссылке для собственных операций. В активном блоке доступны только запрошенные байты, а оставшаяся округлённая ёмкость помечена как недоступная, в том числе для выделений вне рабочих потоков или при нулевом лимите. Под MemorySanitizer (MSAN) содержимое повторно используемого кадра снова помечается как неинициализированное. Эти аннотации обнаруживают обращения по устаревшим указателям, пока блок свободен, но не могут обнаружить их после допустимого повторного использования того же адреса.

## Тестирование выделения памяти

Детерминированный тест может привязать собственный кеш к текущему потоку, не полагаясь на планирование исполнительных пулов:

```cpp
TAllocationCache<TAsyncFrameCacheTag> cache(64 * 1024);
TScopedAllocationCache<TAsyncFrameCacheTag> guard(&cache);
```

`TScopedAllocationCache` объявлен в `ydb/library/actors/testlib/scoped_allocation_cache.h`. Вложенная привязка при уничтожении восстанавливает предыдущую. Выделение, освобождение и `GetStats()` должны выполняться в потоке привязки; `cache.GetCachedStats()` считывает число свободных блоков из любого потока. Существующие тесты находятся в `ydb/library/actors/async/ut/frame_cache_ut.cpp` и `ydb/library/actors/core/ut/allocation_cache_ut.cpp`.

## Реализация

Акторы не владеют кешами кадров: метод `IActor::GetAsyncFrameCache()` и учёт `LiveFrames` в исходном кеше удалены, а аргумент с актором для выбора кеша не нужен. Кеш кадров — одно из семейств общей подсистемы кешей выделения памяти; другой компонент может определить собственный тег и зарегистрировать подсистему `TAllocationCacheFamily` с отдельным лимитом.

| Файл в `ydb/library/actors/core/` | Содержимое |
|---|---|
| `allocation_cache.h` | Классы размеров, выделение и освобождение, аннотации санитайзеров, статистика |
| `subsystems/allocation_cache.h` | `TAllocationCacheSubSystem`, кеши каждого исполнительного потока, `TAllocationCacheFamily` |
| `subsystems/allocation_cache_tls.h` | `TAllocationCache<TTag>::GetCurrent()` |
| `subsystems/async_frame_cache.h` | `TAsyncFrameCacheTag` и `TAsyncFrameCache` |
