# admin cluster bridge rollback

{% include [feature_enterprise.md](../../../../_includes/feature_enterprise.md) %}

С помощью команды `admin cluster bridge rollback` можно вернуть кластер, ранее [преобразованный из обычного в bridge](convert.md), в обычный режим с сохранением данных. Команду можно использовать после завершения преобразования, а также если преобразование застряло или было выполнено частично.

Команда преобразует статические группы хранения в обычные, после чего контроллер хранилища преобразует динамические группы и пулы, а состояние bridge удаляется. Затем необходимо вручную удалить `bridge_config` и имена pile из конфигурации и перезапустить узлы без них.

{% include [danger-warning](../_includes/danger-warning.md) %}

{% note warning %}

Успешное завершение команды означает, что статические группы стали обычными и запущен откат остального хранилища, но не означает полного возврата кластера в обычный режим. Полная процедура приведена в разделе [Возврат преобразованного кластера в обычный режим](../../../../devops/deployment-options/manual/bridge-management.md#rollback).

{% endnote %}

Общий вид команды:

```bash
{{ ydb-cli }} [global options...] admin cluster bridge rollback [options...]
```

- `global options` — [глобальные параметры](../global-options.md) CLI;
- `options` — [параметры подкоманды](#options).

Просмотр справки по команде:

```bash
{{ ydb-cli }} admin cluster bridge rollback --help
```

## Параметры подкоманды {#options}

| Имя | Описание |
| --- | --- |
| `--skip-bsc-validation` | Не выполнять предварительную проверку динамических групп контроллером хранилища. Используйте только если контроллер не может запуститься после преобразования, поскольку зависит от статических групп. Параметр не отключает проверки самого отката: блокирующие условия будут показаны командой [list](list.md), а попытки продолжатся автоматически. |

## Требования {#requirements}

- Кластер должен быть преобразован из обычного в bridge. Откат невозможен для кластера, изначально развёрнутого в режиме bridge с несколькими pile, или после удаления исходного pile.
- Исходный pile должен быть единственным оставшимся в кластере и в `bridge_config`; в таком состоянии он может быть только `PRIMARY`, а значит, синхронизирован. Другие pile необходимо заранее [удалить](../../../../devops/deployment-options/manual/bridge-management.md#remove-pile); команда `rollback` не удаляет их сама.
- Не должны выполняться другие операции с pile или их синхронизация. Завершения текущего преобразования в bridge не требуется.
- Каждая группа в режиме bridge должна быть inline-группой в исходном pile: иметь собственные VDisk в нём, синхронизированную часть и не иметь частей в других pile. Декомиссия таких групп не должна выполняться.
- Из `blob_storage_config.storage_pool_pile_overrides` должны быть удалены правила для исходного pile.
- Должно быть включено автоматическое управление конфигурацией. Все статические и подключённые динамические узлы должны работать со сборкой {{ ydb-short-name }}, поддерживающей откат bridge, а все настроенные статические узлы должны передать отчёт о своей конфигурации.

Если предварительная проверка обнаруживает неподдерживаемую группу, команда возвращает ошибку с её идентификатором и не начинает откат. Откат не восстанавливает конфигурацию из старого снимка, не отменяет миграцию на конфигурацию V2 и не заменяет текущую версию {{ ydb-short-name }} на предыдущую.

## Примеры {#examples}

Вернуть преобразованный кластер в обычный режим:

```bash
{{ ydb-cli }} -y admin cluster bridge rollback
```

Без глобального параметра `-y` команда запрашивает подтверждение.

Если контроллер хранилища не может запуститься после преобразования:

```bash
{{ ydb-cli }} -y admin cluster bridge rollback --skip-bsc-validation
```

### Проверка результата {#verify}

С помощью команды `admin cluster bridge list piles` дождитесь завершения отката хранилища:

```bash
{{ ydb-cli }} admin cluster bridge list piles
```

Во время отката вывод содержит:

```text
Rollback: storage in progress
```

Если последняя попытка завершилась ошибкой, вывод содержит `Last attempt has failed (being retried): <error>`. Устраните указанную причину; контроллер хранилища продолжит попытки автоматически. Повторный вызов `rollback` при уже выполняющемся откате не создаёт новую операцию.

После удаления состояния bridge команда `list` сообщает `Bridge configuration still in use` и показывает, сколько узлов всё ещё работают с `bridge_config`. На этом этапе удалите bridge-настройки и перезапустите узлы по [полной процедуре](../../../../devops/deployment-options/manual/bridge-management.md#rollback). После завершения отката команда выводит `Cluster mode: ordinary`.
