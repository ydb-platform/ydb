# admin cluster bridge set-database-mode

{% include [feature_enterprise.md](../../../../_includes/feature_enterprise.md) %}

С помощью команды `admin cluster bridge set-database-mode` можно переключить все пулы хранения базы данных между режимом bridge и обычным режимом. Существующие данные сохраняются. Репликация или удаление избыточных копий продолжается в фоновом режиме после завершения команды.

{% include [danger-warning](../_includes/danger-warning.md) %}

Общий вид команды:

```bash
{{ ydb-cli }} [global options...] admin cluster bridge set-database-mode <mode> --target-database <path> [options...]
```

- `global options` — [глобальные параметры](../global-options.md) CLI;
- `<mode>` — `bridged` для включения репликации bridge или `ordinary` для её отключения;
- `<path>` — абсолютный путь к изменяемой базе данных;
- `options` — [параметры подкоманды](#options).

Просмотр справки по команде:

```bash
{{ ydb-cli }} admin cluster bridge set-database-mode --help
```

## Параметры подкоманды {#options}

| Имя | Описание |
| --- | --- |
| `--target-database <path>` | Обязательный абсолютный путь к изменяемой базе данных. Не изменяет базу данных подключения и аутентификации, заданную глобальным параметром `--database`. |
| `--retain-pile <pile>` | Только при переключении в `ordinary`: сохранить части всех преобразуемых групп в указанном pile. Подробнее см. в разделе [Выбор сохраняемых копий](#retain-pile). |

## Требования {#requirements}

- Кластер должен быть преобразован в режим bridge, и преобразование должно быть завершено.
- Должно быть установлено `bridge_config.enable_non_uniform_storage: true`.
- Добавление или удаление pile не должно выполняться.
- При переключении в `bridged` каждая существующая группа должна находиться внутри одного pile. Группы, охватывающие несколько pile, нельзя преобразовать напрямую.
- Параметр `--retain-pile` можно использовать только с `ordinary`.
- Выбранный с помощью `--retain-pile` pile должен содержать синхронизированные части всех групп, переводимых в `ordinary`.

Для serverless-базы данных укажите её коммунальную базу данных в `--target-database`. Изменение применяется к коммунальной базе и всем её serverless-базам.

Переключение всех пулов базы данных выполняется атомарно: если проверка не пройдена, режим ни одного пула не изменяется. После успешного переключения в `ordinary` части групп вне сохраняемых pile удаляются в фоновом режиме.

Полная процедура приведена в разделе [Переключение режима хранения базы данных](../../../../devops/deployment-options/manual/bridge-management.md#database-mode).

## Выбор сохраняемых копий при переключении в обычный режим {#retain-pile}

У каждой группы в режиме bridge есть по одной части в каждом участвующем pile. При переключении в `ordinary` для каждой такой группы выбирается одна часть, которая сохраняется и становится обычной группой. Остальные части удаляются в фоновом режиме. Пулы, уже использующие обычный режим, не изменяются: команда не переносит их данные в другой pile.

С `--retain-pile <pile>` все преобразуемые группы всех пулов базы данных сохраняют части в одном указанном pile. Можно выбрать `PRIMARY` или другой pile в состоянии `SYNCHRONIZED`; его роль не меняется. В выбранном pile должна быть часть каждой преобразуемой группы в состоянии `SYNCED`. Если это условие не выполняется хотя бы для одной группы, команда завершается с ошибкой и режим ни одного пула не изменяется. Используйте этот параметр, когда важно явно задать размещение данных, например перед удалением другого pile.

Без `--retain-pile` {{ ydb-short-name }} выбирает сохраняемую часть отдельно для каждой группы: ранее назначенную сохраняемую часть; если она не назначена — исходную часть, из которой была создана группа bridge (inline-часть); если её нет — часть в `PRIMARY`. Выбранная часть также должна быть `SYNCED`. Поэтому после предыдущих переключений режима разные группы одной базы данных могут остаться в разных pile: автоматический выбор не собирает все данные базы в одном pile.

Перед переключением проверьте состояние частей групп, как описано в разделе [Проверка результата](#verify).

## Примеры {#examples}

Переключить базу данных `/Root/db1` в режим bridge:

```bash
{{ ydb-cli }} -y admin cluster bridge set-database-mode bridged --target-database /Root/db1
```

Переключить базу данных `/Root/db1` в обычный режим и сохранить данные в `pile-a`:

```bash
{{ ydb-cli }} -y admin cluster bridge set-database-mode ordinary --target-database /Root/db1 --retain-pile pile-a
```

### Проверка результата {#verify}

Успешное завершение команды подтверждает атомарное изменение режима всех пулов базы данных, но не завершение фоновой синхронизации или очистки. Команда `bridge list` не показывает состояние этих операций, а состояния pile могут не измениться.

Чтобы проверить синхронизацию частей групп в режиме bridge или удаление избыточных частей после переключения в обычный режим, используйте системное представление `.sys/ds_groups`, как описано в разделе [Проверка переключения режима хранения](../../../../devops/deployment-options/manual/bridge-management.md#verify-database-mode).
