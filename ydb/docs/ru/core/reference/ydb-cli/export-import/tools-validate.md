# Проверка резервной копии

Команда `tools validate` проверяет целостность резервной копии, созданной командами [`export s3`](./export-s3.md) или [`export nfs`](./export-nfs.md). Проверке подлежат состав файлов, корректность метаданных и контрольные суммы. Команда самостоятельно считывает файлы резервной копии из S3 или из файловой системы, не загружает данные в базу и не требует подключения к {{ ydb-short-name }}.

```bash
{{ ydb-cli }} tools validate s3 [options]
{{ ydb-cli }} tools validate nfs [options]
```

Подкоманды `s3` и `nfs` отличаются только расположением резервной копии. Формат файлов копии описан в статье [Файловая структура выгрузки](./file-structure.md).

{% note warning %}

Успешная проверка означает, что файлы резервной копии не повреждены и согласованы друг с другом. Она не гарантирует, что копию удастся загрузить командой `import`: команда не разбирает содержимое CSV- и Parquet-файлов и не сверяет его со схемой таблицы.

{% endnote %}

## Варианты проверки {#layouts}

Команда поддерживает три варианта проверки, в зависимости от режима создания проверяемой резервной копии и переданных в команду параметров.

**Полная копия** — результат вызова команды `export s3` с `--destination-prefix` или команды `export nfs` с `--fs-path`, выполненных без параметра `--item`. В составе такой копии хранится список выгруженных объектов, и команда проверяет каждый объект из этого списка. Наличие в составе копии дополнительных файлов, не указанных в списке, считается ошибкой.

**Выборочная копия** — результат выгрузки с параметром `--item src=...,dst=...`. В составе такой копии нет отдельного списка выгруженных объектов. Префикс, в котором размещена выборочная копия, содержит директории выгруженных объектов, обнаруживаемые при проверке целостности по наличию файлов метаданных (`scheme.pb` и другим). Команда проверяет каждый найденный объект, в том числе таблицы индексов (даже если они не указаны в метаданных таблицы). Поскольку список выгруженных объектов не хранится в составе выборочной копии, по умолчанию команда не может проверить полноту такой копии (например, обнаружить ошибочно удалённый из неё объект). Для проверки полноты в команду необходимо передать список ожидаемых имён объектов в виде [параметра `--expected-objects`](#expected-objects).

**Отдельный объект** — путь к директории одной выгруженной таблицы, представления, топика и т. п. Для таблицы команда проверяет также индексы и потоки изменений, перечисленные в её `metadata.json`, и таблицы индексов, найденные в её директории.

Вариант проверки выбирается автоматически. Путь считается полной копией, если присутствуют файлы со списком объектов. В противном случае команда проверяет путь как выборочную копию или как отдельный объект — в зависимости от содержимого. Параметр `--format` позволяет задать вариант проверки явно:

- `auto` (по умолчанию) — выбирать вариант автоматически, как описано выше;
- `full` — проверять путь как полную копию;
- `item` — проверять путь как выборочную копию. Если содержимое при этом похоже на полную копию, команда выводит предупреждение.

## Список ожидаемых объектов {#expected-objects}

Чтобы проверить полноту выборочной копии, укажите в параметре `--expected-objects` путь к текстовому файлу со списком объектов. В каждой строке файла — имя объекта относительно проверяемого пути, например `dir1/table1`; пустые строки игнорируются. Объект, который есть в копии, но не указан в файле, вызывает предупреждение. Объект, указанный в файле, но отсутствующий в копии, — ошибка. Таблицы индексов в директории указанного объекта считаются его частью, перечислять их отдельно не нужно. Для полной копии этот параметр не используется: список объектов содержится в самой копии.

Сформировать такой список можно командой `tools list-objects`. Она выводит имена объектов схемы, расположенных по указанному пути базы данных: таблиц, колоночных таблиц, представлений и топиков. Каждое имя выводится с новой строки в формате, подходящем для `--expected-objects`:

```bash
{{ ydb-cli }} [connection options] tools list-objects [options]
```

В отличие от `tools validate`, эта команда подключается к базе данных.

| Параметр | Описание |
| --- | --- |
| `-p`, `--path PATH` | Путь к директории или объекту в базе данных: относительно корня базы либо полный путь, начинающийся с пути базы данных. По умолчанию: `.` — корень базы данных. |
| `--include-index-data` | Дополнительно перечислить таблицы индексов, которые при выгрузке с параметром `--include-index-data` записываются как отдельные объекты. |
| `-o`, `--output PATH` | Записать список в файл. По умолчанию список выводится в стандартный вывод. |

Имена выводятся относительно `--path`. Если `--path` указывает на отдельную таблицу, выводится `.`, а таблицы её индексов (при `--include-index-data`) — в виде `index_name/indexImplTable`.

## Что проверяется {#checks}

Файлы метаданных — `scheme.pb`, `permissions.pb`, `metadata.json`, описания потоков изменений и топиков, SQL- и protobuf-файлы схемы, а также файлы в `SchemaMapping` — должны быть доступны для чтения и содержать обязательный минимальный набор полей с описанием объекта. Для таблицы обязательны непустой список колонок, тип каждой колонки и первичный ключ, состоящий из колонок этого списка.

Количество файлов `data_...` должно соответствовать числу партиций, заданному в `scheme.pb`. Поле `uniform_partitions` задаёт это число напрямую, а для `partition_at_keys` оно равно числу `split_points` плюс один. Если ни одно из этих полей не задано, таблица состоит из одной партиции и должна содержать один файл данных — `data_00`. Номера файлов должны идти подряд от `0` до `N-1`, без пропусков, дубликатов и лишних файлов. Имена файлов должны иметь вид `data_00.csv`, `data_01.parquet` и т. д.; номер состоит не менее чем из двух цифр, а при сжатии к имени добавляется суффикс `.zst`.

Контрольные суммы хранятся рядом с проверяемыми файлами: для `data_00.csv` это `data_00.csv.sha256`, для сжатого `data_00.csv.zst` — тот же `data_00.csv.sha256`. В файле записана контрольная сумма SHA-256 несжатого содержимого. Контрольные суммы метаданных и файлов схемы проверяются всегда. Если параметр `--scheme-only` не указан, команда проверяет и контрольные суммы данных: читает файлы в потоковом режиме, при необходимости распаковывает данные, сжатые zstd, и вычисляет хеш по мере чтения. С параметром `--scheme-only` файлы данных не читаются — команда лишь проверяет, что для каждого из них есть файл контрольной суммы и в нём записан шестнадцатеричный SHA-256.

Контрольные суммы данных можно проверить только в копиях, для которых они были рассчитаны при создании. Начиная с версии 25.3 контрольные суммы рассчитываются по умолчанию. Такие копии содержат `"checksum": "sha256"` в `metadata.json` копии и `"version": 1` в метаданных объектов. Если файлов контрольных сумм нет, проверка без `--scheme-only` завершается ошибкой.

Зашифрованные копии не проверяются: файлы с расширением `.enc` и поле `encryption` в `metadata.json` копии считаются ошибкой. Параметр `--encryption-key-file` принимается только для совместимости с командами `import`, а переданный ключ не используется. Если ключ указан, но копия не содержит зашифрованных файлов, команда выводит предупреждение.

При ошибке ввода-вывода команда повторяет чтение файла, постепенно увеличивая интервал между попытками со 100 мс до 2 с. Число попыток задаётся параметром `--retries`.

## Ошибки и предупреждения {#errors}

По умолчанию команда не останавливается на первой ошибке и сообщает обо всех найденных проблемах. Параметр `--fail-fast` прерывает проверку после первой ошибки: остальные пути из `--item` не проверяются, однако уже запущенные в других потоках проверки выполняются до конца. Предупреждения проверку не прерывают и на код возврата не влияют.

## Параметры командной строки {#pars}

### Общие параметры {#common}

| Параметр | Описание |
| --- | --- |
| `--format FORMAT` | Ожидаемый [вариант проверки](#layouts): `auto`, `full` или `item`. По умолчанию: `auto`. |
| `--scheme-only` | Проверить только состав файлов, структуру метаданных и наличие файлов контрольных сумм. Файлы данных не читаются. |
| `--fail-fast` | Остановиться на первой ошибке. По умолчанию сообщаются все ошибки. |
| `--threads NUM` | Максимальное число потоков. Параллельно проверяются и разные объекты, и файлы данных одного объекта. По умолчанию используется число доступных процессоров минус один, но не менее одного потока. |
| `--retries NUM` | Число попыток чтения файла копии при ошибках ввода-вывода. По умолчанию: `10`. |
| `--encryption-key-file PATH` | Принимается только для совместимости с [`import s3`](./import-s3.md) и [`import nfs`](./import-nfs.md); ключ не используется. Как и в этих командах, ключ можно передать шестнадцатеричной строкой в переменной окружения `YDB_ENCRYPTION_KEY` или путём к файлу в `YDB_ENCRYPTION_KEY_FILE`. Зашифрованные файлы в любом случае считаются ошибкой. |
| `--item PROPERTY=VALUE,...` | Проверяемый объект. Параметр можно указать несколько раз. Свойства: `source` (`src`, `s`) — путь к копии или объекту; `destination` (`dst`, `d`) принимается для совместимости с `import` и игнорируется. |
| `--expected-objects PATH` | Файл со [списком ожидаемых объектов](#expected-objects) для копии из отдельных объектов. |

### Параметры S3 {#s3}

Параметры подключения те же, что у [`import s3`](./import-s3.md); см. [Соединение и аутентификация с S3](./auth-s3.md).

| Параметр | Описание |
| --- | --- |
| `--s3-endpoint ENDPOINT` | Адрес S3. Обязательный. |
| `--scheme SCHEME` | `http` или `https`. По умолчанию: `https`. |
| `--bucket BUCKET` | Имя бакета. Обязательный. |
| `--access-key STRING` | Идентификатор ключа AWS. Переменная окружения: `AWS_ACCESS_KEY_ID`. |
| `--secret-key STRING` | Секретный ключ AWS. Переменная окружения: `AWS_SECRET_ACCESS_KEY`. |
| `--aws-profile STRING` | Имя профиля в `~/.aws/credentials`. Переменная окружения: `AWS_PROFILE`. По умолчанию: `default`. |
| `--use-virtual-addressing BOOL` | Стиль адресации бакета: `true` — virtual-hosted-style (по умолчанию), `false` — path-style. |
| `--source-prefix PREFIX` | Префикс ключей полной копии или отдельного объекта. Используется, если не задан `--item`. |

При указании `--item` свойство `source`, как и в `import s3`, содержит полный префикс ключей в бакете; значение `--source-prefix` к нему не добавляется.

### Параметры NFS {#nfs}

| Параметр | Описание |
| --- | --- |
| `--fs-path PATH` | Директория с резервной копией. Обязательный. Без `--item` проверяется сама директория; с `--item` свойство `source` каждого объекта задаётся относительно неё, как в `import nfs`. |

## Результат {#result}

Каждая найденная ошибка или предупреждение выводится в стандартный поток ошибок отдельной строкой в формате `путь: сообщение`; предупреждения начинаются со слова `warning:`. В конце выводится итоговая строка:

- `Backup validation succeeded: checked N object(s)` — ошибок нет; код возврата — `0`. Если были предупреждения, их число указывается в этой же строке.
- `Backup validation failed: N issue(s), checked M object(s)` — найдена хотя бы одна ошибка; код возврата — `1`.

## Примеры {#examples}

Проверка полной копии в S3:

```bash
{{ ydb-cli }} tools validate s3 \
  --s3-endpoint storage.example.net --bucket mybucket \
  --source-prefix backup/2026-10-01
```

Проверка одной выгруженной таблицы без чтения файлов данных:

```bash
{{ ydb-cli }} tools validate s3 \
  --s3-endpoint storage.example.net --bucket mybucket \
  --item source=backup/2026-10-01/dir1/table1 \
  --scheme-only
```

Проверка копии на смонтированной файловой системе:

```bash
{{ ydb-cli }} tools validate nfs --fs-path /mnt/backup/2026-10-01
```

Проверка одной таблицы из этой копии:

```bash
{{ ydb-cli }} tools validate nfs \
  --fs-path /mnt/backup/2026-10-01 \
  --item source=dir1/table1
```

Проверка полноты копии, созданной с параметром `--item`. Сначала команда `tools list-objects` сохраняет в файл `objects.txt` список объектов из директории `dir1` базы данных; для подключения к базе используется профиль `quickstart` (см. [{#T}](../profile/create.md#quickstart)). Затем команда `tools validate` сверяет резервную копию с полученным списком:

```bash
{{ ydb-cli }} -p quickstart tools list-objects --path dir1 --output objects.txt
{{ ydb-cli }} tools validate nfs \
  --fs-path /mnt/backup/2026-10-01/dir1 \
  --expected-objects objects.txt
```
