# Проверка резервной копии

Команда `tools validate` проверяет целостность резервной копии или выгруженного объекта схемы, созданных командами [`export s3`](./export-s3.md) или [`export nfs`](./export-nfs.md). Она проверяет состав файлов, согласованность метаданных и контрольные суммы. Команда считывает файлы непосредственно из S3 или файловой системы, не загружая данные в базу, поэтому подключение к {{ ydb-short-name }} не требуется.

```bash
{{ ydb-cli }} tools validate s3 [options]
{{ ydb-cli }} tools validate nfs [options]
```

Подкоманды `s3` и `nfs` отличаются только расположением выгруженных файлов. Они используют одинаковые формат файлов и структуру директорий, описанные в статье [Файловая структура выгрузки](./file-structure.md).

{% note warning %}

Успешная проверка означает, что проверенные командой файлы не повреждены и согласованы друг с другом. При использовании `--scheme-only` содержимое файлов данных не проверяется. Результат проверки не гарантирует, что выгрузку удастся загрузить командой `import`: `tools validate` не разбирает строки CSV- и Parquet-файлов и не сверяет их значения со схемой таблицы.

{% endnote %}

## Поддерживаемые варианты выгрузки {#layouts}

Команда поддерживает следующие варианты:

- **Полная резервная копия**, созданная без `--item`. Команда проверяет каждый объект из списка, сохранённого в копии, и считает ошибкой наличие объектов схемы, которых нет в этом списке.
- **Выгрузка с `--item src=...,dst=...`**. Она не содержит полного списка объектов. Команда проверяет все найденные поддерживаемые объекты схемы, включая индексные таблицы. Без параметра [`--expected-objects`](#expected-objects) команда предупреждает, что полнота выгрузки не проверена. Чтобы обнаружить отсутствующие объекты, передайте их ожидаемый список.
- **Отдельный выгруженный объект**, например таблица, представление или топик. Для таблицы команда также проверяет выгруженные индексы и потоки изменений.

По умолчанию команда определяет вариант выгрузки автоматически. Его можно задать явно с помощью `--format`:

- `auto` (по умолчанию) — определить полную резервную копию, а в остальных случаях проверить выгрузку с `--item` или отдельный объект;
- `full` — требовать полную резервную копию;
- `item` — считать указанный путь выгрузкой с `--item` или отдельным объектом. Если путь похож на полную резервную копию, команда выводит предупреждение и не проверяет хранящийся в ней список объектов.

## Список ожидаемых объектов {#expected-objects}

Чтобы проверить полноту выгрузки с `--item`, укажите в параметре `--expected-objects` путь к текстовому файлу со списком ожидаемых объектов. Каждая непустая строка должна содержать имя объекта относительно проверяемого пути, например `dir1/table1`. Если найденного в выгрузке объекта нет в файле, команда выводит предупреждение. Если указанный в файле объект отсутствует в выгрузке, команда сообщает об ошибке. Индексные таблицы внутри директории именованного объекта перечислять отдельно не нужно.

Не используйте `--expected-objects` с полной резервной копией: список объектов уже входит в её состав, а указание этого параметра приводит к ошибке.

Используйте `--expected-objects` с одним исходным путём. Если указать несколько параметров `--item`, команда сопоставит каждый из них со всем списком ожидаемых объектов.

Сформировать файл можно командой `tools list-objects`. Она выводит имена строковых и колоночных таблиц, представлений и топиков, расположенных по указанному пути в базе данных. Каждое имя выводится с новой строки в формате, подходящем для `--expected-objects`:

```bash
{{ ydb-cli }} [connection options] tools list-objects [options]
```

В отличие от `tools validate`, эта команда подключается к базе данных.

| Параметр | Описание |
| --- | --- |
| `-p`, `--path PATH` | Путь к директории или объекту в базе данных: относительно корня базы либо полный путь, начинающийся с пути базы данных. По умолчанию: `.` — корень базы данных. |
| `--include-index-data` | Дополнительно перечислить индексные таблицы. Используйте параметр, если выгрузка создана с `--include-index-data true`. |
| `-o`, `--output PATH` | Записать список в файл. По умолчанию список выводится в стандартный вывод. |

Имена выводятся относительно `--path`. Если `--path` указывает на отдельный поддерживаемый объект, он обозначается как `.`. Чтобы включить индексные таблицы для таблицы, обозначенной как `.`, используйте `--include-index-data`.

Полученный список описывает объекты, находящиеся по пути `--path` в момент запуска команды. Он соответствует выгрузке, если в ней сохранена такая же структура. Если при выгрузке исключались или перемещались объекты, отредактируйте файл в соответствии с ожидаемым составом проверяемого пути.

## Что проверяется {#checks}

Команда проверяет:

- наличие и доступность для чтения обязательных файлов схемы, метаданных и данных;
- поддерживаемый формат и внутреннюю согласованность метаданных;
- наличие файла данных для каждой партиции таблицы, а также единообразие формата и сжатия файлов данных;
- согласованность перечисленных или найденных объектов схемы, а также связанных с ними индексов и потоков изменений;
- наличие и корректность обязательных файлов контрольных сумм.

Если параметр `--scheme-only` не задан, команда считывает каждый файл данных и сравнивает контрольную сумму SHA-256 его несжатого содержимого с сохранённой при выгрузке. Если в выгрузке нет контрольных сумм данных, команда сообщает об ошибке, поскольку не может подтвердить целостность содержимого. Чтобы проверить только структуру такой выгрузки, используйте `--scheme-only`: в этом режиме содержимое файлов данных не считывается.

Параметр `--metadata-checksums` управляет проверкой контрольных сумм метаданных выгрузки, включая `metadata.json` и `SchemaMapping/mapping.json`. В режиме `auto`, используемом по умолчанию, учитывается информация о контрольных суммах в самой выгрузке. Режим `always` требует метаданные и файлы их контрольных сумм независимо от этой информации; выгрузки, созданные без таких файлов, проверку не проходят. Режим `ignore` отключает проверку контрольных сумм метаданных и допускает отсутствие объектных файлов `metadata.json`.

Зашифрованные резервные копии не поддерживаются. Зашифрованные файлы считаются ошибкой, даже если передан ключ шифрования.

## Ошибки и предупреждения {#errors}

По умолчанию команда не останавливается на первой ошибке и сообщает обо всех найденных проблемах. С параметром `--fail-fast` команда останавливается после первой ошибки, однако параллельно выполняемые проверки могут сообщить дополнительные ошибки. Предупреждения не прерывают проверку и не влияют на код завершения.

## Параметры командной строки {#pars}

### Общие параметры {#common}

| Параметр | Описание |
| --- | --- |
| `--format FORMAT` | Ожидаемый [вариант выгрузки](#layouts): `auto`, `full` или `item`. По умолчанию: `auto`. |
| `--scheme-only` | Проверить состав файлов, метаданные и файлы контрольных сумм, не считывая содержимое файлов данных. |
| `--metadata-checksums MODE` | Режим проверки метаданных выгрузки: `auto` учитывает информацию в выгрузке, `always` требует метаданные и файлы их контрольных сумм, `ignore` отключает проверку контрольных сумм метаданных и допускает отсутствие объектных `metadata.json`. По умолчанию: `auto`. |
| `--fail-fast` | Остановиться на первой ошибке. По умолчанию сообщаются все ошибки. |
| `--threads NUM` | Максимальное число потоков проверки. По умолчанию используется число доступных процессоров минус один, но не менее одного потока. |
| `--retries NUM` | Число попыток выполнить операцию ввода-вывода с хранилищем после ошибки. По умолчанию: `10`. |
| `--encryption-key-file PATH` | Принимается для совместимости с [`import s3`](./import-s3.md) и [`import nfs`](./import-nfs.md), но ключ не используется. Зашифрованные файлы считаются ошибкой. Если передать ключ для незашифрованной выгрузки, команда выводит предупреждение. Соответствующие переменные окружения: `YDB_ENCRYPTION_KEY_FILE` и `YDB_ENCRYPTION_KEY`. |
| `--item PROPERTY=VALUE,...` | Проверяемый объект. Параметр можно указать несколько раз. Свойства: `source` (`src`, `s`) — путь к копии или объекту; `destination` (`dst`, `d`) принимается для совместимости с `import` и игнорируется. |
| `--expected-objects PATH` | Файл со [списком ожидаемых объектов](#expected-objects) для выгрузки с `--item`. |

### Параметры S3 {#s3}

Параметры подключения те же, что у [`import s3`](./import-s3.md); см. [Соединение и аутентификация с S3](./auth-s3.md).

| Параметр | Описание |
| --- | --- |
| `--s3-endpoint ENDPOINT` | Эндпоинт S3. Обязательный параметр. |
| `--scheme SCHEME` | `http` или `https`. По умолчанию: `https`. |
| `--bucket BUCKET` | Имя бакета. Обязательный параметр. |
| `--access-key STRING` | Идентификатор ключа доступа. Переменная окружения: `AWS_ACCESS_KEY_ID`. |
| `--secret-key STRING` | Секретный ключ доступа. Переменная окружения: `AWS_SECRET_ACCESS_KEY`. |
| `--aws-profile STRING` | Имя профиля в `~/.aws/credentials`. Переменная окружения: `AWS_PROFILE`. По умолчанию: `default`. |
| `--use-virtual-addressing BOOL` | Стиль адресации бакета: `true` — virtual-hosted-style (по умолчанию), `false` — path-style. |
| `--source-prefix PREFIX` | Префикс ключей полной резервной копии, выгрузки с `--item` или отдельного объекта. Обязателен, если не задан `--item`. |

При указании `--item` свойство `source`, как и в `import s3`, содержит полный префикс ключей в бакете, а `--source-prefix` игнорируется.

### Параметры NFS {#nfs}

| Параметр | Описание |
| --- | --- |
| `--fs-path PATH` | Директория с выгруженными файлами. Обязательный. Без `--item` проверяется сама директория; с `--item` свойство `source` каждого объекта задаётся относительно неё, как в `import nfs`. |

## Результат {#result}

Ход проверки и диагностические сообщения выводятся в стандартный поток ошибок. В сообщениях об ошибках указывается соответствующий путь в формате `путь: сообщение`, а строки с предупреждениями начинаются с `warning:`. Затем команда выводит итоговую строку:

- `Backup validation succeeded: checked N object(s)` — ошибок нет; код завершения — `0`. Если были предупреждения, их число указывается в этой же строке.
- `Backup validation failed: N issue(s), checked M object(s)` — найдена хотя бы одна ошибка; код завершения — `1`.

Сообщение об успехе выводится в стандартный поток вывода, а о неудаче — в стандартный поток ошибок. Если были предупреждения, их число добавляется к любой из итоговых строк. Следующая строка содержит длительность проверки, общий объём прочитанных данных и среднюю скорость чтения.

## Примеры {#examples}

Проверка полной копии в S3:

```bash
{{ ydb-cli }} tools validate s3 \
  --s3-endpoint storage.example.net --bucket mybucket \
  --source-prefix backup/2026-10-01
```

Проверка одной выгруженной таблицы без чтения файлов данных:

```bash
{{ ydb-cli }} tools validate s3 \
  --s3-endpoint storage.example.net --bucket mybucket \
  --item source=backup/2026-10-01/dir1/table1 \
  --scheme-only
```

Проверка копии на смонтированной файловой системе:

```bash
{{ ydb-cli }} tools validate nfs --fs-path /mnt/backup/2026-10-01
```

Проверка одной таблицы из этой копии:

```bash
{{ ydb-cli }} tools validate nfs \
  --fs-path /mnt/backup/2026-10-01 \
  --item source=dir1/table1
```

Проверка полноты выгрузки с `--item`. В примере предполагается, что содержимое директории `dir1` базы данных выгружено без исключений в `/mnt/backup/items-2026-10-01/dir1`. Сначала команда `tools list-objects` сохраняет ожидаемый список объектов в файл `objects.txt`; для подключения к базе используется профиль `quickstart` (см. [{#T}](../profile/create.md#quickstart)). Затем команда `tools validate` сверяет выгрузку с полученным списком:

```bash
{{ ydb-cli }} -p quickstart tools list-objects --path dir1 --output objects.txt
{{ ydb-cli }} tools validate nfs \
  --fs-path /mnt/backup/items-2026-10-01/dir1 \
  --expected-objects objects.txt
```
