# Проверка резервной копии

Команда `tools validate` проверяет целостность резервной копии, созданной командами [`export s3`](./export-s3.md) или [`export nfs`](./export-nfs.md). Проверка выполняется в этом процессе и не восстанавливает данные в базу, поэтому соединение с {{ ydb-short-name }} не требуется.

```bash
{{ ydb-cli }} tools validate s3 [options]
{{ ydb-cli }} tools validate nfs [options]
```

Подкоманды `s3` и `nfs` отличаются только способом чтения резервной копии. Состав файлов описан в статье [Файловая структура выгрузки](./file-structure.md).

## Что проверяется {#checks}

Путь считается полной резервной копией, если в его `metadata.json` указано `"kind": "SimpleExportV0"`. В этом случае проверяются `SchemaMapping` и каждый объект из этого списка. Такие метаданные записываются, когда выгрузка использует `--destination-prefix` или `--fs-path`.

Выгрузка через `--item src=...,dst=...` не создаёт этот файл и `SchemaMapping`. Префикс назначения — это каталог выгруженных объектов (`scheme.pb`, `create_view.sql` и остальные файлы схемы). Команда находит эти объекты и проверяет каждый из них, в том числе таблицы реализации индексов внутри каталога таблицы, даже если метаданные таблицы их не перечисляют. Состава объектов, которые не были выгружены, в такой копии нет.

Любой другой путь считается одним выгруженным объектом (таблица, представление, топик и т. д.). Путь к таблице проверяет эту таблицу, включая индексы и потоки изменений из её `metadata.json` и найденные под ней таблицы индексов. Путь к полной копии проверяет всю копию.

Файлы метаданных (`scheme.pb`, `permissions.pb`, `metadata.json`, описания потоков изменений и топиков, SQL и protobuf-файлы схемы, `SchemaMapping`) должны читаться и содержать минимально необходимые поля. Для таблицы это непустой список колонок, тип каждой колонки и первичный ключ, который является подмножеством этих колонок.

Число партиций в `scheme.pb` должно совпадать с набором файлов `data_...`. `uniform_partitions` задаёт это число. `partition_at_keys` означает число `split_points` плюс один. Если не задано ни то ни другое, у таблицы одна партиция — `data_00`. Индексы должны идти как `0 .. N-1` без пропусков, дубликатов и лишних файлов. Канонические имена: `data_00.csv`, `data_01.parquet` и т. д. (не меньше двух цифр), возможно с суффиксом `.zst`.

Без флага `--scheme-only` дополнительно проверяется содержимое файлов данных. Контрольные суммы экспорта — это SHA-256 несжатого текста, записанные в соседний файл, например `data_00.csv.sha256` (то же имя используется, если объект называется `data_00.csv.zst`). Контрольные суммы метаданных и схемы проверяются в обоих режимах. В режиме `--scheme-only` байты данных не читаются: команда лишь проверяет, что sidecar каждой партиции существует и содержит hex-дайджест SHA-256.

Проверка содержимого требует эти sidecar-файлы. Выгрузки с контрольными суммами (значение по умолчанию начиная с 25.3) записывают `"checksum": "sha256"` в `metadata.json` копии и `"version": 1` в метаданные объекта. Если sidecar-файлов нет, проверка без `--scheme-only` завершается ошибкой.

Зашифрованные копии (объекты `.enc` или поле `encryption` в метаданных копии) обнаруживаются и отклоняются. Команда принимает те же параметры ключа, что и `import`, но не расшифровывает файлы копии.

## Параметры командной строки {#pars}

### Общие параметры {#common}

| Параметр | Описание |
| --- | --- |
| `--scheme-only` | Проверить только состав файлов и структуру метаданных. Содержимое файлов данных не читается. |
| `--retries NUM` | Число попыток чтения файла копии после ошибки ввода-вывода. По умолчанию: `10`. |
| `--encryption-key-file PATH` | Путь к файлу ключа шифрования, в том же виде, что у [`import s3`](./import-s3.md) / [`import nfs`](./import-nfs.md). Ключ также можно передать в `YDB_ENCRYPTION_KEY` шестнадцатеричной строкой, а путь к файлу — в `YDB_ENCRYPTION_KEY_FILE`. Зашифрованные файлы всё равно отклоняются. |
| `--item PROPERTY=VALUE,...` | Объект для проверки. Параметр можно указать несколько раз. Свойства: `source` (`src`, `s`) — путь внутри копии; `destination` (`dst`, `d`) принимается для совместимости с `import` и игнорируется. |

### Параметры S3 {#s3}

Параметры соединения совпадают с [`import s3`](./import-s3.md). См. [Соединение и аутентификация с S3](./auth-s3.md).

| Параметр | Описание |
| --- | --- |
| `--s3-endpoint ENDPOINT` | Адрес S3. Обязательный. |
| `--scheme SCHEME` | `http` или `https`. По умолчанию: `https`. |
| `--bucket BUCKET` | Имя бакета. Обязательный. |
| `--access-key STRING` | Идентификатор ключа AWS. Переменная окружения: `AWS_ACCESS_KEY_ID`. |
| `--secret-key STRING` | Секретный ключ AWS. Переменная окружения: `AWS_SECRET_ACCESS_KEY`. |
| `--aws-profile STRING` | Именованный профиль в `~/.aws/credentials`. Переменная окружения: `AWS_PROFILE`. По умолчанию: `default`. |
| `--use-virtual-addressing BOOL` | `true` — virtual-hosted-style URL (по умолчанию). `false` — path-style URL. |
| `--source-prefix PREFIX` | Префикс ключа полной копии или одного объекта. Используется, если не задан `--item`. |

При указании `--item` свойство `source` — это полный префикс ключа в бакете, как у `ydb import s3`. Оно не дописывается к `--source-prefix`.

### Параметры NFS {#nfs}

| Параметр | Описание |
| --- | --- |
| `--fs-path PATH` | Каталог с резервной копией. Обязательный. Без `--item` проверяется сам этот каталог. С `--item` каждый `source` задаётся относительно этого каталога, как у `ydb import nfs`. |

## Результат {#result}

Для корректной копии печатается `Backup validation succeeded`, код выхода — 0. Каждая проблема печатается в виде `path: message`. Если найдена хотя бы одна проблема, код выхода — 1.

## Примеры {#examples}

Проверка полной копии в S3:

```bash
{{ ydb-cli }} tools validate s3 \
  --s3-endpoint storage.example.net --bucket mybucket \
  --source-prefix backup/2026-10-01
```

Проверка одной выгруженной таблицы без чтения байтов данных:

```bash
{{ ydb-cli }} tools validate s3 \
  --s3-endpoint storage.example.net --bucket mybucket \
  --item source=backup/2026-10-01/dir1/table1 \
  --scheme-only
```

Проверка каталога копии на смонтированной файловой системе:

```bash
{{ ydb-cli }} tools validate nfs --fs-path /mnt/backup/2026-10-01
```

Проверка одной таблицы в этом каталоге:

```bash
{{ ydb-cli }} tools validate nfs \
  --fs-path /mnt/backup/2026-10-01 \
  --item source=dir1/table1
```
