# Проверка резервной копии

Команда `tools validate` проверяет целостность резервной копии или выгруженного объекта схемы, созданных командами [`export s3`](./export-s3.md) или [`export nfs`](./export-nfs.md). Она проверяет состав файлов, согласованность метаданных и контрольные суммы. Команда считывает файлы непосредственно из S3 или файловой системы, не загружая данные в базу, поэтому подключение к {{ ydb-short-name }} не требуется.

```bash
{{ ydb-cli }} tools validate s3 [options]
{{ ydb-cli }} tools validate nfs [options]
```

Подкоманды `s3` и `nfs` отличаются только расположением выгруженных файлов. Они используют одинаковые формат файлов и структуру директорий, описанные в статье [Файловая структура выгрузки](./file-structure.md).

{% note warning %}

Успешная проверка означает, что выгруженные файлы не повреждены и согласованы друг с другом. Она не гарантирует, что их удастся загрузить командой `import`: команда не разбирает строки CSV- и Parquet-файлов и не сверяет их значения со схемой таблицы.

{% endnote %}

## Поддерживаемые варианты выгрузки {#layouts}

Команда поддерживает следующие варианты:

- **Полная резервная копия**, созданная без `--item`: с параметром `--destination-prefix` для `export s3` или `--fs-path` для `export nfs`. Команда проверяет каждый объект из списка, сохранённого в копии, и сообщает об объектах схемы, которых нет в этом списке.
- **Выгрузка с `--item src=...,dst=...`**. Она не содержит полного списка объектов. Команда проверяет все найденные поддерживаемые объекты схемы, включая таблицы индексов. Чтобы обнаружить отсутствующие в выгрузке объекты, передайте их ожидаемый список в параметре [`--expected-objects`](#expected-objects).
- **Отдельный выгруженный объект**, например таблица, представление или топик. Для таблицы команда также проверяет выгруженные индексы и потоки изменений.

По умолчанию команда определяет вариант выгрузки автоматически. Его можно задать явно с помощью `--format`:

- `auto` (по умолчанию) — определить полную резервную копию, а в остальных случаях проверить выгрузку с `--item` или отдельный объект;
- `full` — требовать полную резервную копию;
- `item` — считать указанный путь выгрузкой с `--item` или отдельным объектом. Если путь похож на полную резервную копию, команда выводит предупреждение и не проверяет хранящийся в ней список объектов.

## Список ожидаемых объектов {#expected-objects}

Чтобы проверить полноту выгрузки с `--item`, укажите в параметре `--expected-objects` путь к текстовому файлу со списком ожидаемых объектов. Каждая непустая строка должна содержать имя объекта относительно проверяемого пути, например `dir1/table1`. Если найденного в выгрузке объекта нет в файле, команда выводит предупреждение. Если указанный в файле объект отсутствует в выгрузке, команда сообщает об ошибке. Таблицы индексов внутри директории указанного объекта перечислять отдельно не нужно.

Не используйте `--expected-objects` с полной резервной копией: список объектов уже входит в её состав, а одновременное использование двух списков приводит к ошибке.

Сформировать файл можно командой `tools list-objects`. Она выводит имена строковых и колоночных таблиц, представлений и топиков, расположенных по указанному пути базы данных. Каждое имя выводится с новой строки в формате, подходящем для `--expected-objects`:

```bash
{{ ydb-cli }} [connection options] tools list-objects [options]
```

В отличие от `tools validate`, эта команда подключается к базе данных.

| Параметр | Описание |
| --- | --- |
| `-p`, `--path PATH` | Путь к директории или объекту в базе данных: относительно корня базы либо полный путь, начинающийся с пути базы данных. По умолчанию: `.` — корень базы данных. |
| `--include-index-data` | Дополнительно перечислить таблицы индексов, выгружаемые как отдельные объекты при использовании `--include-index-data`. |
| `-o`, `--output PATH` | Записать список в файл. По умолчанию список выводится в стандартный вывод. |

Имена выводятся относительно `--path`. Если `--path` указывает на отдельную таблицу, она обозначается как `.`.

## Что проверяется {#checks}

Команда проверяет:

- наличие и доступность для чтения обязательных файлов схемы, метаданных и данных;
- поддерживаемый формат и внутреннюю согласованность метаданных;
- соответствие числа и формата файлов данных метаданным таблицы;
- согласованность перечисленных или найденных объектов схемы, а также связанных с ними индексов и потоков изменений;
- наличие и корректность обязательных файлов контрольных сумм.

При полной проверке команда считывает каждый файл данных и сравнивает контрольную сумму SHA-256 его несжатого содержимого с сохранённой при выгрузке. Если контрольных сумм данных нет, подтвердить целостность содержимого невозможно, поэтому команда сообщает об ошибке. С параметром `--scheme-only` содержимое файлов данных не считывается: проверяются только состав файлов, метаданные и файлы контрольных сумм.

Параметр `--metadata-checksums` определяет, обязательны ли файлы контрольных сумм для `metadata.json`. В режиме `auto`, используемом по умолчанию, команда следует информации о контрольных суммах в самой выгрузке. Режим `always` требует такие файлы и для старых выгрузок, а `ignore` отключает их проверку.

Зашифрованные резервные копии не поддерживаются. Зашифрованные файлы считаются ошибкой, даже если передан ключ шифрования.

## Ошибки и предупреждения {#errors}

По умолчанию команда не останавливается на первой ошибке и сообщает обо всех найденных проблемах. Параметр `--fail-fast` после первой ошибки прекращает запуск новых проверок; уже начатые проверки могут завершиться. Предупреждения не прерывают проверку и не влияют на код завершения.

## Параметры командной строки {#pars}

### Общие параметры {#common}

| Параметр | Описание |
| --- | --- |
| `--format FORMAT` | Ожидаемый [вариант проверки](#layouts): `auto`, `full` или `item`. По умолчанию: `auto`. |
| `--scheme-only` | Проверить состав файлов, метаданные и файлы контрольных сумм, не считывая содержимое файлов данных. |
| `--metadata-checksums MODE` | Режим проверки контрольных сумм `metadata.json`: `auto` следует информации в выгрузке, `always` требует файл контрольной суммы для каждого `metadata.json`, `ignore` отключает их проверку. По умолчанию: `auto`. |
| `--fail-fast` | Остановиться на первой ошибке. По умолчанию сообщаются все ошибки. |
| `--threads NUM` | Максимальное число потоков проверки. По умолчанию используется число доступных процессоров минус один, но не менее одного потока. |
| `--retries NUM` | Число попыток чтения файла копии при ошибках ввода-вывода. По умолчанию: `10`. |
| `--encryption-key-file PATH` | Принимается для совместимости с [`import s3`](./import-s3.md) и [`import nfs`](./import-nfs.md), но ключ не используется. Зашифрованные файлы считаются ошибкой. Соответствующие переменные окружения: `YDB_ENCRYPTION_KEY_FILE` и `YDB_ENCRYPTION_KEY`. |
| `--item PROPERTY=VALUE,...` | Проверяемый объект. Параметр можно указать несколько раз. Свойства: `source` (`src`, `s`) — путь к копии или объекту; `destination` (`dst`, `d`) принимается для совместимости с `import` и игнорируется. |
| `--expected-objects PATH` | Файл со [списком ожидаемых объектов](#expected-objects) для выгрузки с `--item`. |

### Параметры S3 {#s3}

Параметры подключения те же, что у [`import s3`](./import-s3.md); см. [Соединение и аутентификация с S3](./auth-s3.md).

| Параметр | Описание |
| --- | --- |
| `--s3-endpoint ENDPOINT` | Адрес S3. Обязательный. |
| `--scheme SCHEME` | `http` или `https`. По умолчанию: `https`. |
| `--bucket BUCKET` | Имя бакета. Обязательный. |
| `--access-key STRING` | Идентификатор ключа AWS. Переменная окружения: `AWS_ACCESS_KEY_ID`. |
| `--secret-key STRING` | Секретный ключ AWS. Переменная окружения: `AWS_SECRET_ACCESS_KEY`. |
| `--aws-profile STRING` | Имя профиля в `~/.aws/credentials`. Переменная окружения: `AWS_PROFILE`. По умолчанию: `default`. |
| `--use-virtual-addressing BOOL` | Стиль адресации бакета: `true` — virtual-hosted-style (по умолчанию), `false` — path-style. |
| `--source-prefix PREFIX` | Префикс ключей полной резервной копии, выгрузки с `--item` или отдельного объекта. Обязателен, если не задан `--item`. |

При указании `--item` свойство `source`, как и в `import s3`, содержит полный префикс ключей в бакете; значение `--source-prefix` к нему не добавляется.

### Параметры NFS {#nfs}

| Параметр | Описание |
| --- | --- |
| `--fs-path PATH` | Директория с выгруженными файлами. Обязательный. Без `--item` проверяется сама директория; с `--item` свойство `source` каждого объекта задаётся относительно неё, как в `import nfs`. |

## Результат {#result}

Ход проверки и диагностические сообщения выводятся в стандартный поток ошибок. В сообщениях об ошибках указывается соответствующий путь в формате `путь: сообщение`, а строки с предупреждениями начинаются с `warning:`. Затем команда выводит итоговую строку:

- `Backup validation succeeded: checked N object(s)` — ошибок нет; код завершения — `0`. Если были предупреждения, их число указывается в этой же строке.
- `Backup validation failed: N issue(s), checked M object(s)` — найдена хотя бы одна ошибка; код завершения — `1`.

Сообщение об успехе выводится в стандартный поток вывода, а о неудаче — в стандартный поток ошибок. Следующая строка содержит длительность проверки, общий объём прочитанных данных и среднюю скорость чтения.

## Примеры {#examples}

Проверка полной копии в S3:

```bash
{{ ydb-cli }} tools validate s3 \
  --s3-endpoint storage.example.net --bucket mybucket \
  --source-prefix backup/2026-10-01
```

Проверка одной выгруженной таблицы без чтения файлов данных:

```bash
{{ ydb-cli }} tools validate s3 \
  --s3-endpoint storage.example.net --bucket mybucket \
  --item source=backup/2026-10-01/dir1/table1 \
  --scheme-only
```

Проверка копии на смонтированной файловой системе:

```bash
{{ ydb-cli }} tools validate nfs --fs-path /mnt/backup/2026-10-01
```

Проверка одной таблицы из этой копии:

```bash
{{ ydb-cli }} tools validate nfs \
  --fs-path /mnt/backup/2026-10-01 \
  --item source=dir1/table1
```

Проверка полноты копии, созданной с параметром `--item`. Сначала команда `tools list-objects` сохраняет в файл `objects.txt` список объектов из директории `dir1` базы данных; для подключения к базе используется профиль `quickstart` (см. [{#T}](../profile/create.md#quickstart)). Затем команда `tools validate` сверяет резервную копию с полученным списком:

```bash
{{ ydb-cli }} -p quickstart tools list-objects --path dir1 --output objects.txt
{{ ydb-cli }} tools validate nfs \
  --fs-path /mnt/backup/2026-10-01/dir1 \
  --expected-objects objects.txt
```
