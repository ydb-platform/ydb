# pool set-bridge-mode

С помощью подкоманды `pool set-bridge-mode` можно переключать пул хранения кластера bridge между [режимом bridge и обычным режимом](../../concepts/bridge.md#storage-pools), сохраняя идентификаторы групп и данные.

Общий вид команды:

```bash
ydb-dstool [global options ...] pool set-bridge-mode [options ...]
```

- `global options` — [глобальные параметры](global-options.md);
- `options` — [параметры подкоманды](#options).

Просмотр справки по команде:

```bash
ydb-dstool pool set-bridge-mode --help
```

## Параметры подкоманды {#options}

| Параметр | Описание |
| --- | --- |
| `--pool-name <database:kind>` | Изменяемый пул хранения, например `/Root/db1:ssd`. Повторите параметр, чтобы изменить несколько пулов одним запросом. Обязательный параметр. |
| `--bridged` | Перевести пул в режим bridge. Каждая группа получает часть в каждом pile с фоновой синхронизацией. Несовместимо с `--ordinary`. |
| `--ordinary` | Перевести пул в обычный режим. Каждая группа в режиме bridge сохраняет одну часть, а остальные удаляются. Несовместимо с `--bridged`. |
| `--retain-pile <name>` | С `--ordinary` — pile, часть в котором сохраняет каждая группа. По умолчанию группа сохраняет часть, из которой была переведена в режим bridge, её встроенный pile или часть в primary pile. |
| `--format <FORMAT>` | Формат вывода: `pretty` (по умолчанию) или `json`. |

Необходимо указать ровно один из параметров `--bridged` и `--ordinary`. Параметр `--retain-pile` можно использовать только с `--ordinary`.

## Требования {#requirements}

- Кластер должен быть преобразован в режим bridge, преобразование должно быть завершено, а `bridge_config.enable_non_uniform_storage` — включён.
- Не должно быть ожидающих операций добавления или удаления pile.
- Для перевода пула в режим bridge каждая группа должна находиться в одном pile. Группы `mirror-3-dc` в нескольких ДЦ нельзя преобразовать напрямую.
- Для перевода пула в обычный режим сохраняемая часть должна быть `SYNCED`, а её pile должен оставаться в кворуме данных. Если сохраняемая часть не является авторитетной, её pile также должен быть `SYNCHRONIZED`.

Эксплуатационные ограничения и безопасность синхронизации описаны в разделе [Изменение режима пула хранения](../../devops/deployment-options/manual/bridge-management.md#pool-mode).

## Примеры {#examples}

Перевести пул `/Root/db1:ssd` в режим bridge:

```bash
ydb-dstool pool set-bridge-mode --pool-name /Root/db1:ssd --bridged
```

Новые части создаются немедленно и синхронизируются в фоновом режиме. До завершения синхронизации каждая группа зависит только от исходного pile. Не отключайте его во время синхронизации.

Перевести тот же пул в обычный режим и сохранить его части в `pile-a`:

```bash
ydb-dstool pool set-bridge-mode --pool-name /Root/db1:ssd --ordinary --retain-pile pile-a
```

Остальные части удаляются в фоновом режиме примерно через 30 секунд. После этого пул недоступен при каждом отключении `pile-a`, а сам pile нельзя удалить.

Проверяйте состояния pile с помощью [bridge list](../ydb-cli/commands/bridge/list.md), а прогресс — по счётчикам синхронизации BSC. `TDefineStoragePool` не может изменить режим существующего пула; используйте эту команду.
