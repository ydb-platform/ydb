# Как подготовить воспроизводимый пример (repro)

Воспроизводимый пример — **repro** — минимальный самодостаточный набор шагов: YQL, команды CLI, скрипт или небольшой проект, с которыми ошибка повторяется стабильно. Хороший repro помогает понять, где проблема — в {{ ydb-short-name }} или в коде приложения. Он ускоряет диагностику и упрощает написание регрессионных тестов.

## Когда нужен repro {#when-needed}

Подготовьте repro, если сообщаете о проблеме в работе {{ ydb-short-name }}:

- ошибке или неожиданном результате запроса;
- сбое SDK или CLI;
- разном поведении одного и того же сценария при запуске разными способами ({{ ydb-ui-name }}, CLI или SDK).

{% note tip %}

Если воспроизвести ошибку стабильно не удаётся, всё равно сообщите о ней: опишите обстоятельства, окружение и приложите логи.

{% endnote %}

## Что включить в issue {#must-include}

**Issue** — это сообщение о проблеме в репозитории на GitHub. Структурируйте его по разделам ниже:

1. **Описание бага** (`Bug description`) — кратко, что не так. Само сообщение об ошибке лучше прикладывать текстом, а не скриншотом.
2. **Шаги воспроизведения** (`Steps to reproduce`) — нумерованный список действий, минимальный YQL или код. Укажите, где вы запускали сценарий: [{{ ydb-ui-name }}](../reference/ydb-ui/index.md), [{{ ydb-short-name }} CLI](../reference/ydb-cli/index.md) или [{{ ydb-short-name }} SDK](../reference/ydb-sdk/index.md).
3. **Ожидаемое поведение** (`Expected behavior`) — что должно произойти при корректной работе.
4. **Фактическое поведение** (`Actual behavior`) — что произошло на самом деле. Укажите, повторяется ли проблема стабильно.
5. **Окружение** (`Environment`) — версия или ветка {{ ydb-short-name }}, способ развёртывания и при необходимости версия клиента. Укажите, например, Docker-образ и его тег, бинарную сборку, кластер или другое окружение.

Сценарий должен быть самодостаточным и минимальным. Оставьте в нём только необходимое для воспроизведения: нужные объекты, тестовые данные, запрос или код.

Иногда ошибка не воспроизводится одним запросом и видна только в клиентском коде. Так бывает, например, в работе с сессиями или топиками. В этом случае подготовьте короткий скрипт на SDK или небольшой проект. При необходимости приложите ссылку на публичный репозиторий и команду запуска.

Дополнительно добавьте скриншот или фрагмент лога, если без них шаги неоднозначны.

{% note warning %}

Issue, которое вы создали на GitHub, доступно всем. Не публикуйте токены, пароли, строки подключения, адреса внутренних хостов и реальные данные — замените их тестовыми значениями.

{% endnote %}

## Пример оформления {#minimal-example}

Ниже — учебный образец структуры issue. Он показывает, как оформить разделы, а не описывает реальный баг. Значения в разделе **Окружение** приведены для примера: укажите версию {{ ydb-short-name }} и способ развёртывания, которые используете вы.

{% cut "Пример repro" %}

**Описание бага** (`Bug description`):

Запрос с `ORDER BY ... DESC` возвращает строки в порядке возрастания, а не убывания.

**Шаги воспроизведения** (`Steps to reproduce`):

1. Откройте [{{ ydb-ui-name }}](../reference/ydb-ui/index.md).
2. Создайте таблицу:

    ```yql
    DROP TABLE IF EXISTS `demo_items`;

    CREATE TABLE `demo_items` (
        `id` Uint64 NOT NULL,
        `price` Uint64 NOT NULL,
        PRIMARY KEY (`id`)
    );
    ```

3. Добавьте данные и выполните выборку:

    ```yql
    UPSERT INTO `demo_items` (`id`, `price`) VALUES
        (1, 10),
        (2, 30),
        (3, 20);

    SELECT `id`, `price`
    FROM `demo_items`
    ORDER BY `price` DESC;
    ```

**Ожидаемое поведение** (`Expected behavior`):

Строки возвращаются в порядке убывания `price`: `(2, 30)`, `(3, 20)`, `(1, 10)`.

**Фактическое поведение** (`Actual behavior`):

Строки возвращаются в порядке возрастания `price`: `(1, 10)`, `(3, 20)`, `(2, 30)`. Проблема воспроизводится при каждом запуске.

**Окружение** (`Environment`):

- {{ ydb-short-name }}: `25.4`
- Способ развёртывания: Docker-образ `{{ ydb_local_docker_image }}:25.4`

{% endcut %}

## Типичные ошибки {#anti-patterns}

- Только фразы «не работает» или «иногда падает», или одна ссылка на pull request без подробного описания проблемы.
- Ссылки на закрытые ресурсы, например, на внутреннюю wiki или приватный репозиторий.
- Рабочее приложение целиком вместо минимального сценария.

## Куда отправить сообщение о баге {#where-to-report}

Перед созданием issue поищите похожие среди [существующих](https://github.com/ydb-platform/ydb/issues).

Если похожего issue нет, [заведите новое](https://github.com/ydb-platform/ydb/issues/new) в [репозитории {{ ydb-short-name }}](https://github.com/ydb-platform/ydb) на GitHub.

{% note warning %}

Не сообщайте об уязвимостях безопасности в публичных issue. Напишите на [security@ydb.tech](mailto:security@ydb.tech) в соответствии с [политикой безопасности](https://github.com/ydb-platform/ydb/blob/main/SECURITY.md).

{% endnote %}
