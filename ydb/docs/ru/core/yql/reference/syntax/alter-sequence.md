# ALTER SEQUENCE

`ALTER SEQUENCE` изменяет параметры существующего [генератора последовательности (sequence)](../../../concepts/glossary.md#sequence), связанного с колонкой [серийного типа](../types/serial.md). Команда позволяет изменить шаг выдачи значений или возобновить генерацию с нужного значения, например, после загрузки данных с явно заданными идентификаторами.

## Синтаксис

```yql
ALTER SEQUENCE [IF EXISTS] path_to_sequence
    [INCREMENT [BY] increment]
    [START [WITH] start_value]
    [RESTART [[WITH] restart_value]];
```

Нужно указать хотя бы одно действие: `INCREMENT`, `START` или `RESTART`. Действия можно записывать в любом порядке, без запятых. Каждое действие допускается не более одного раза в одном запросе. Неуказанные параметры сохраняют свои значения; если `RESTART` отсутствует, позиция генератора не сбрасывается.

Слова `BY` и `WITH` необязательны и не меняют поведение команды. Например, `INCREMENT 5` эквивалентно `INCREMENT BY 5`, а `RESTART 1000` эквивалентно `RESTART WITH 1000`.

## Параметры

* `path_to_sequence`: путь к объекту sequence. Для серийной колонки он имеет вид `<path_to_table>/_serial_column_<column_name>`, где `<path_to_table>` задаёт путь таблицы, а `<column_name>` задаёт имя колонки. Например, для таблицы `/Root/users` и колонки `user_id` используется путь `/Root/users/_serial_column_user_id`. Подробнее о размещении объекта см. в статье [{#T}](../../../concepts/datamodel/sequence.md).
* `IF EXISTS`: отсутствие sequence по указанному пути не считается ошибкой. Без этой конструкции запрос к отсутствующему объекту завершается ошибкой.
* `INCREMENT [BY] increment`: устанавливает шаг выдачи значений. `increment` задаётся положительным целочисленным литералом; нулевой шаг недопустим. При создании sequence шаг равен 1, но пропуск `INCREMENT` в `ALTER SEQUENCE` сохраняет уже установленный шаг.
* `START [WITH] start_value`: сохраняет стартовое значение для последующих сбросов через `RESTART` без аргумента. Само по себе действие `START` не изменяет следующее выдаваемое значение. При создании sequence стартовое значение равно 1.
* `RESTART [[WITH] restart_value]`: сбрасывает позицию генератора. Если `restart_value` указан, выдача возобновляется с этого значения. Без аргумента используется сохранённое стартовое значение, в том числе заданное через `START` в этом же запросе. `RESTART` с явным аргументом не изменяет сохранённое стартовое значение.

Стартовое значение и значение для `RESTART` задаются целочисленными литералами и проверяются на соответствие допустимому диапазону sequence. Значения за пределами диапазона приводят к ошибке. Учитывайте также [диапазон типа серийной колонки](../types/serial.md#types-and-value-ranges).

{% note warning %}

`RESTART` не удаляет и не изменяет строки таблицы и не ищет свободное значение. Сброс может привести к повторной выдаче уже записанных значений и конфликтам при совпадении всего первичного ключа. Подробнее см. в разделе [{#T}](../types/serial.md#explicit-values).

{% endnote %}

## Примеры

Для примеров используется таблица `users` из раздела [{#T}](../types/serial.md#usage-example), созданная в базе данных `/Root`. Для другой базы или таблицы замените путь sequence на соответствующий абсолютный путь.

### Изменение шага и позиции генератора

Установим шаг 5 и возобновим выдачу со значения 1000:

```yql
ALTER SEQUENCE `/Root/users/_serial_column_user_id`
    INCREMENT BY 5
    RESTART 1000;
```

Последующие обращения к генератору выдадут 1000, 1005, 1010 и так далее. Сохранённое стартовое значение не изменится.

### Изменение стартового значения

Чтобы последующие сбросы без аргумента начинали выдачу с 1000, сначала изменим стартовое значение, а затем выполним `RESTART`:

```yql
ALTER SEQUENCE `/Root/users/_serial_column_user_id`
    INCREMENT BY 5
    START WITH 1000;
ALTER SEQUENCE `/Root/users/_serial_column_user_id` RESTART;
```

Первый запрос сохраняет стартовое значение и шаг, но не сбрасывает позицию. Второй возобновляет выдачу с 1000. Если требуется сразу сохранить новое стартовое значение и сбросить позицию, `START WITH 1000` и `RESTART` можно указать в одном запросе.
