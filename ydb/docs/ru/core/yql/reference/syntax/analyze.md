# ANALYZE

`ANALYZE` собирает статистику таблицы и её столбцов. [Стоимостной оптимизатор {{ ydb-short-name }}](../../../concepts/query_execution/optimizer.md) использует её, чтобы оценивать объём обрабатываемых данных и выбирать план запроса.

Оператор работает с одной таблицей и завершается после обновления статистики.

## Синтаксис

```yql
ANALYZE <path_to_table> [ (<column_name> [, ...]) ] [SAMPLE <rate>]
```

Параметры:

* `path_to_table`: путь к таблице.
* `column_name`: столбцы, для которых нужно собрать статистику. Если список не задан, обрабатываются все столбцы таблицы.
* `SAMPLE <rate>`: сэмплированный сбор статистики. `rate` задаёт долю выборки и имеет тип `Double`. Значение должно находиться в полуинтервале `(0, 1]`. Без `SAMPLE` или с `SAMPLE 1` таблица читается целиком.

## Примеры

Сбор статистики для таблицы `orders`:

```yql
-- Для всех столбцов
ANALYZE orders;

-- Для выбранных столбцов
ANALYZE orders (customer_id, amount);

-- По выборке с долей 0.1
ANALYZE orders SAMPLE 0.1;
```

## Собираемая статистика

`ANALYZE` собирает статистику выбранных столбцов: оценки числа различных значений, их частоты и распределения. Набор статистики зависит от типа и содержимого столбца.

Чтобы собирать многоколоночную статистику, добавьте раздел `STATISTICS` в [CREATE TABLE](create_table/statistics.md) или [ALTER TABLE](alter_table/statistics.md). При вызове `ANALYZE` укажите все столбцы этой статистики или не задавайте список столбцов.

## Сэмплированный сбор статистики {#sampling}

Чтобы собрать сэмплированную статистику, добавьте `SAMPLE` с долей меньше `1`.

* В строковой таблице каждая строка независимо включается в выборку с вероятностью `rate`.
* В колоночной таблице случайно выбираются шарды. Читается хотя бы один шард; при небольшом числе шардов могут быть прочитаны все.

При сборе по выборке оценка числа различных значений сохраняется только для колоночных таблиц, у которых прочитаны все шарды.

Статистика по выборке хранится отдельно от полной и заменяется при следующем полном `ANALYZE`. Сбор по выборке не влияет на расписание [фонового обновления](../../../reference/configuration/statistics_config.md#enable-background-column-stats-collection): оно отсчитывается от последнего полного `ANALYZE`.

## Отслеживание прогресса

SQL операция `ANALYZE` выполняется синхронно и ожидает завершения. При этом создаётся фоновая операция для наблюдаемости. Используйте команду [operation list](../../../reference/ydb-cli/operation-list.md) для отслеживания прогресса фоновых операций `ANALYZE`.
