# CHECK TABLE INDEX

`CHECK TABLE INDEX` проверяет, соответствует ли содержимое индекса данным исходной таблицы. Оператор сравнивает ожидаемые и сохранённые записи индекса в одном снимке и сообщает о недостающих и лишних записях, а также о несовпадении значений.

## Синтаксис

Укажите путь к таблице и имя проверяемого индекса.

```yql
CHECK TABLE <table_path> INDEX <index_name>;
```

- `table_path` — имя или путь к таблице. Действуют те же правила, что и в [`SELECT`](select/index.md).
- `index_name` — имя индекса этой таблицы.

## Требования

- Индекс должен быть готов. Для строковых таблиц поддерживаются синхронные [вторичные индексы](create_table/secondary_index.md), в том числе уникальные, и [JSON-индексы](create_table/json_index.md) с некомпактным хранением.
- Запрос должен выполняться одним блоком и возвращать единственный набор результатов, который формирует `CHECK TABLE INDEX`.
- Явная транзакция должна использовать режим [Snapshot Read-Only](../../../concepts/transactions.md#snapshot-read-only). Без явного управления транзакцией оператор выполняется в неявной транзакции Snapshot Read-Only.
- Проверка завершается ошибкой, если снимок становится недоступен, индекс заменяется во время проверки или несколько строк основной таблицы имеют одинаковый сохранённый идентификатор документа.
- Для остальных типов индексов и форматов хранения возвращается `UNSUPPORTED` с сообщением `Index validation is not implemented for <type>`.
- Используйте Query Service, в том числе метод `ExecuteScript`. Устаревшие методы `ExecuteYqlScript` и `StreamExecuteYqlScript` возвращают `UNSUPPORTED`.

## Результат {#result}

Оператор возвращает одну строку со следующими столбцами.

| Столбец | Тип | Описание |
| --- | --- | --- |
| `SnapshotStep` | `Uint64` | Шаг снимка, из которого прочитаны таблица и индекс. |
| `SnapshotTxId` | `Uint64` | Идентификатор транзакции в том же снимке. |
| `Status` | `String` | `OK`, если расхождений нет, иначе `INCONSISTENT`. |
| `Missing` | `Uint64` | Число ожидаемых записей, отсутствующих в индексе. |
| `Extra` | `Uint64` | Число сохранённых записей индекса, для которых нет ожидаемых записей. |
| `ValueMismatch` | `Uint64` | Число записей с совпадающим ключом и различающимися значениями, например в столбцах `COVER`. |
| `EmptyTokenPostings` | `Uint64` | Число сохранённых записей с пустым токеном в JSON-индексе с префиксом. Эти записи также учитываются в `Extra`. |
| `Sample` | Список структур | До 100 примеров расхождений. Каждый пример в закодированном виде занимает до 8 КиБ. Счётчики учитывают все расхождения. |

Пример расхождения содержит `Kind`, `Role`, `Reason` и поля `Key`, `Expected`, `Actual`. Тип `Key` — `List<Struct<Name:String,Type:String,Value:String?>>`. `Expected` и `Actual` — опциональные списки того же типа. Поле отсутствует, если соответствующей записи нет. Каждый элемент списка содержит имя и тип столбца, а также его значение в виде `String`. Если значение столбца равно `NULL`, поле `Value` отсутствует.

Если отображение идентификаторов строк нарушено, в выборку не попадают лишние записи JSON-индекса, для определения которых требуется это отображение. Эти записи входят в счётчики.

## Пример

Чтобы проверить индекс `idx` таблицы `Docs`, выполните следующий запрос.

```yql
CHECK TABLE Docs INDEX idx;
```

Пусть запись индекса для `Tag = 10` и `Id = 1` содержит `NULL` в покрывающем столбце `Data`, а в таблице хранится `original`. Оператор обнаружит одно несовпадение значений.

| SnapshotStep | SnapshotTxId | Status | Missing | Extra | ValueMismatch | EmptyTokenPostings | Sample |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `120` | `42` | `INCONSISTENT` | `0` | `0` | `1` | `0` | Одна запись `VALUE_MISMATCH` для `Tag = 10`, `Id = 1`. |

В списке `Key` этого примера есть элементы `Tag` и `Id` со значениями `Value` `"10"` и `"1"`. В списках `Expected` и `Actual` есть элемент с именем `Data`. В `Expected` его `Value` равно `"original"`, а в `Actual` поле `Value` отсутствует.
