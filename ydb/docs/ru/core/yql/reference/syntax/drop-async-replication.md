# DROP ASYNC REPLICATION

Вызов `DROP ASYNC REPLICATION` удаляет экземпляр [асинхронной репликации](../../../concepts/async-replication.md). По умолчанию вместе с экземпляром асинхронной репликации [удаляются](../../../concepts/async-replication.md#drop):

* автоматически созданные [потоки изменений](../../../concepts/glossary.md#changefeed);
* [объекты-реплики](../../../concepts/glossary.md#replica-object) (опционально).

## Синтаксис {#syntax}

```yql
DROP ASYNC REPLICATION <name> [CASCADE] [FORCE]
```

где:

* `name` — имя экземпляра асинхронной репликации.
* `CASCADE` — каскадное удаление объектов-реплик, созданных в рамках данного экземпляра асинхронной репликации.
* `FORCE` удаляет завершённую репликацию локально, без обращения к источнику и получения его учётных данных. Если параметр не указан, сохраняется обычная очистка ресурсов источника. Параметр применяется только к асинхронной репликации. При совместном использовании указывайте `CASCADE` перед `FORCE`.

## Удаление без доступа к источнику {#force}

Используйте `FORCE`, если источник недоступен и автоматически созданные потоки изменений нужно оставить на нём. Сначала запросите [принудительное завершение](alter-async-replication.md). Успешный ответ на `ALTER` подтверждает принятие этого запроса:

```yql
ALTER ASYNC REPLICATION my_replication
SET (STATE = 'DONE', FAILOVER_MODE = 'FORCE');
```

После принятия запроса выполните `FORCE DROP`. Команда дождётся завершения локальных операций перед удалением репликации. Чтобы сохранить таблицы назначения и данные:

```yql
DROP ASYNC REPLICATION my_replication FORCE;
```

Сохранённые таблицы остаются доступны для записи. Чтобы также удалить принадлежащие репликации таблицы назначения, добавьте `CASCADE`:

```yql
DROP ASYNC REPLICATION my_replication CASCADE FORCE;
```

Чтобы проверить фактическое состояние завершения, используйте [`ydb scheme describe`](../../../reference/ydb-cli/commands/scheme-describe.md) с выводом в JSON:

```bash
ydb scheme describe my_replication --format proto-json-base64
```

Наличие поля `done` в ответе означает, что репликация фактически перешла в состояние `DONE`. `FORCE DROP` можно выполнить, пока завершение ещё идёт: команда закончит оставшиеся локальные операции без ожидания доступа к источнику.

Локальное завершение и удаление могут занимать время и продолжаются после перезапуска базы назначения. Таблица, созданная с тем же именем после удаления исходной таблицы назначения, не принадлежит репликации и сохраняется.

{% note warning %}

`FORCE` безвозвратно удаляет метаданные очистки ресурсов источника. Потоки изменений, потребители и их конфигурация на источнике остаются без изменений. Восстановление соединения с источником не запускает отложенную очистку; ненужные ресурсы источника следует удалить отдельно. Если нужна обычная очистка, не указывайте `FORCE`.

{% endnote %}

Используйте `FORCE` только после того, как все развёрнутые версии сервера и все допустимые версии для отката поддерживают этот параметр и восстановление операций.

## Примеры {#examples}

Рассмотрим примеры удаления экземпляра асинхронной репликации, созданного следующим запросом:

```yql
CREATE ASYNC REPLICATION my_replication
FOR original_table AS replica_table
WITH (
    CONNECTION_STRING = 'grpcs://example.com:2135/?database=/Root/another_database',
    TOKEN_SECRET_PATH = 'my_secret'
);
```

Удаление экземпляра асинхронной репликации и автоматически созданного потока изменений в таблице `original_table`, таблица `replica_table` остается:

```yql
DROP ASYNC REPLICATION my_replication;
```

Удаление экземпляра асинхронной репликации, автоматически созданного потока изменений в таблице `original_table` и таблицы `replica_table`:

```yql
DROP ASYNC REPLICATION my_replication CASCADE;
```
