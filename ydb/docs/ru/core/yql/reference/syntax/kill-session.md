# KILL SESSION

`KILL SESSION` принудительно завершает [сессию выполнения запросов](../../../concepts/query_execution/execution_process.md#sessions) в текущей базе данных. Команда позволяет остановить запрос, создающий нежелательную нагрузку, или закрыть ненужную долгоживущую сессию.

Команда выполняется через Query Service и может завершать сессии как Query Service, так и Table Service, в том числе на другой ноде. Сессии чтения и записи топиков и сессии сервиса координации этой командой не завершаются.

## Синтаксис {#syntax}

Для завершения одной сессии укажите её идентификатор в [бэктиках](lexer.md#keywords-and-ids):

```yql
KILL SESSION `<session_id>`;
```

Где `<session_id>` - значение колонки `SessionId` из системного представления [`.sys/query_sessions`](../../../dev/system-views.md#query-sessions).

Для программного вызова передавайте идентификатор отдельным параметром типа `Utf8`, объявленным с помощью [`DECLARE`](declare.md):

```yql
DECLARE $session_id AS Utf8;
KILL SESSION $session_id;
```

Значение `$session_id` передаётся через SDK или другой клиент отдельно от текста запроса. Параметр должен содержать полный ID существующей сессии; `NULL` и пустая строка недопустимы. В этой форме бэктики не используются.

Текущая версия поддерживает один ID на оператор. Список ID и выборка ID из подзапроса не поддерживаются.

## Пример: найти и завершить сессию {#examples}

Сначала найдите сессии, в которых запрос выполняется не менее 30 секунд. Следующий [`SELECT`](select/index.md) использует [`CurrentUtcTimestamp`](../builtins/basic.md#current-utc) и [литерал `Interval`](../types/primitive.md):

```yql
SELECT SessionId, UserSID, QueryStartAt, Query
FROM `.sys/query_sessions`
WHERE State = "EXECUTING"
  AND QueryStartAt <= CurrentUtcTimestamp() - Interval("PT30S")
ORDER BY QueryStartAt
LIMIT 20;
```

Выберите нужный `SessionId` из результата и выполните отдельный запрос. Например:

```yql
KILL SESSION `ydb://session/3?node_id=52910&id=MWFmNGYwYTAtYzJkN2RhOWEtZmFkMDhlMTUtZjU0ZDE0OTA%3D`;
```

ID в примере необходимо заменить на идентификатор сессии из вашей базы.

## Права доступа {#permissions}

Для выполнения команды проверяются [права доступа](grant.md#permissions-list) на корне текущей базы данных:

- Пользователь с правом `CONNECT` (`ydb.database.connect`) может завершать свои сессии. Владение определяется совпадением непустых [SID](../../../security/authorization.md#sid) вызывающего пользователя и создателя сессии. Общая группа пользователей сама по себе не означает владение.
- Для завершения чужих сессий дополнительно требуется `UPDATE ROW` (`ydb.granular.update_row`) на корне базы. Это право на таблице или поддиректории недостаточно.
- Администраторы кластера, а также администраторы базы при включённом [`enable_database_admin`](../../../reference/configuration/feature_flags.md), могут завершать любые сессии в этой базе.

Например, следующий [`GRANT`](grant.md) разрешает пользователю `session_operator` завершать любые сессии базы `/Root/my_database`:

```yql
GRANT CONNECT, UPDATE ROW ON `/Root/my_database` TO session_operator;
```

Права могут быть выданы непосредственно пользователю или его группе. Наборы прав, включающие `UPDATE ROW`, также подходят при наличии `CONNECT`.

## Результат и ограничения {#behavior}

Команда не возвращает результирующий набор. Статус `SUCCESS` означает, что сессия удалена после завершения её очистки, включая откат открытых транзакций.

Если выполняющийся на сессии запрос удалось отменить, его клиент получает `CANCELLED` и сообщение о завершении через `KILL SESSION`. Сообщение содержит SID инициатора, если он известен. [Обработка ошибок](../../../reference/ydb-sdk/error_handling.md) должна учитывать, что административно отменённый запрос не следует автоматически запускать заново.

{% note warning %}

Завершение сессии не отменяет уже зафиксированные изменения. Если запись дошла до стадии, на которой отмена уже невозможна, она может завершиться успешно. DDL-операция, уже принятая на исполнение, также может продолжить выполнение после закрытия сессии.

{% endnote %}

`KILL SESSION` выполняется вне пользовательской транзакции, поскольку закрытие другой сессии нельзя откатить вместе с изменениями данных. В SDK используйте режим без явно заданной транзакции, например `TTxControl::NoTx()` в C++ Query Client. Через устаревший `TableService/ExecuteSchemeQuery` команда не выполняется.

Нельзя завершить сессию, на которой выполняется сама команда. Используйте другую сессию для вызова `KILL SESSION`.

Отправляйте `KILL SESSION` отдельным запросом, не объединяя его с запросами к данным.

Если ожидание завершения истекло по таймауту или связь оборвалась, удаление могло уже начаться и продолжиться. Проверьте наличие сессии повторно; повторное завершение уже удалённой сессии возвращает ошибку.

## Ошибки {#errors}

При отказе команда возвращает статус и сообщение с причиной. Основные случаи:

| Статус | Причина |
| --- | --- |
| `BAD_REQUEST` | Неверный формат ID или недопустимое значение параметра. Ошибки типа параметра могут быть обнаружены раньше, при компиляции запроса. |
| `UNAUTHORIZED` | Недостаточно прав. Для пользователя без права завершать чужие сессии отсутствие сессии и отказ доступа возвращают одинаковое сообщение `Session not found or access denied`. |
| `PRECONDITION_FAILED` | Сессия не найдена при наличии права завершать любые сессии; попытка завершить сессию самой команды; выполнение внутри пользовательской транзакции. |
| `GENERIC_ERROR` | Неподдерживаемое смешивание `KILL SESSION` с запросами к данным. |
| `TIMEOUT` | Истёк срок ожидания завершения операции. |
| `UNAVAILABLE` | Не удалось связаться с нодой, владеющей сессией, или доставить запрос. |
| `UNSUPPORTED` | Функциональность выключена фичефлагом. |
