# Условные обозначения синтаксиса команд YQL

Блоки синтаксиса в справочнике YQL записаны в виде синопсиса — схемы команды, которая показывает состав конструкций, их порядок и обязательность. Это человекочитаемая нотификация, которая позволяет удобно представлять запись YQL-команд.

## Обозначения

| Обозначение | Значение |
|-------------|----------|
| `KEYWORD` | Ключевое слово. Пишется буквально; в документации набрано прописными буквами, в запросе регистр не важен. |
| `<name>` | Значение, которое подставляете вы: имя объекта, тип данных, выражение. Угловые скобки в запрос не входят. |
| `[ ... ]` | Необязательная конструкция. |
| `{ A \| B }` | Обязательный выбор: укажите ровно один вариант. |
| `[ A \| B ]` | Необязательный выбор: укажите один вариант или не указывайте ничего. |
| `...` | Предыдущую конструкцию можно повторить. |
| `[, ...]` | Предыдущую конструкцию можно повторить через запятую. |
| `( )`, `,`, `=` и другие знаки | Часть запроса, пишутся буквально. |

`<имя_конструкции>` — именованная подконструкция (например, `<column_definition>`). В запрос не подставляется; раскрывается отдельным блоком «`<имя>` — это» ниже синопсиса.

`[, ...]` относится к **последней** именованной или неделимой конструкции на той же строке.

Вложенные скобки читайте изнутри наружу: во внешней необязательной конструкции могут быть свои необязательные части и свои варианты выбора.

Если конструкция слишком объёмна для основного блока, её выносят в отдельный блок после синопсиса со словами «где `<имя>` — это».

## Примеры

### Обязательные части

```yql
TRUNCATE TABLE <table_name>;
```

`TRUNCATE TABLE` пишется буквально, вместо `<table_name>` подставьте имя таблицы:

```yql
TRUNCATE TABLE my_table;
```

### Необязательная конструкция

```yql
DROP VIEW [IF EXISTS] <view_name>
```

Допустимы оба варианта:

```yql
DROP VIEW recent_series;
DROP VIEW IF EXISTS recent_series;
```

### Повторение и вложенность

```yql
CREATE TABLE [IF NOT EXISTS] <table_name> (
    <column_definition> [, ...]
    , PRIMARY KEY ( <column_name> [, ...] )
)
[WITH ( <setting_name> = <setting_value> [, ...] )]
```

Определение колонки вынесено в `<column_definition>`, поэтому `[, ...]` однозначно указывает на повторение всего определения через запятую. Так же поступают с другими объёмными частями команды: на странице справочника они раскрываются отдельными блоками «`<имя>` — это».

Запятая перед `PRIMARY KEY` обязательна. В `PRIMARY KEY` и в блоке `WITH` элементы тоже перечисляются через запятую, но сами эти конструкции ведут себя по-разному: `PRIMARY KEY` обязателен, а весь блок `WITH` можно не указывать.

Определение колонки:

```yql
<column_name> <column_data_type> [<column_option> ...]
```

`<column_option>` — один из вариантов:

```yql
{ FAMILY <family_name>
| NULL
| NOT NULL
| DEFAULT <default_value>
| COMPRESSION ( [ algorithm = <algorithm_name> [, level = <value>] ] )
| ENCODING ( [ { OFF | DICT } ] )
}
```

Конструкция `[<column_option> ...]` допускает несколько опций подряд: на каждом повторении выбирается один вариант из `{ ... }`, поэтому допустимы сочетания вроде `NOT NULL` и `DEFAULT` для одной колонки.

Внешние фигурные скобки показывают, что каждая опция — один из перечисленных вариантов. Конструкция `{ OFF | DICT }` задает обязательный выбор внутри необязательной конструкции: если пишете `ENCODING`, круглые скобки обязательны, а значение в них можно опустить или указать одно из двух.

Связанные модификаторы группируют в одной ветке `{ ... | ... }`. Для индекса на странице [{#T}](create_table/index.md) это выглядит так:

```yql
{ GLOBAL [UNIQUE] [SYNC | ASYNC] | LOCAL }
```

Здесь обязательно указать `GLOBAL` или `LOCAL`; `UNIQUE` и `SYNC | ASYNC` относятся только к ветке `GLOBAL`.

### Разделители в списках

Запятая в круглых скобках — часть запроса, в синопсисе она пишется буквально. Если между элементами списка в `( ... )` показана запятая (как перед `PRIMARY KEY` в примере выше), в запросе она обязательна.

Квадратные скобки `[ ... ]` оборачивают целую необязательную конструкцию. Несколько `[ ... ]` подряд — это несколько независимых необязательных частей, а не «запятые между optional-блоками».

## Синтаксис и описание на странице команды

Синопсис в блоке кода с меткой `yql` показывает **форму** запроса: порядок ключевых слов, элементы в угловых скобках, необязательные части и варианты выбора.

Раздел **Параметры** (или отдельные подзаголовки под синопсисом) поясняет **смысл** каждого такого элемента: что подставить в `<table_name>`, когда уместен `IF EXISTS`, какие ограничения на имена. Имя в синопсисе и заголовок параметра на той же странице описывают одну и ту же сущность.

В синопсис не переносят проверки времени выполнения: существует ли объект, совместимы ли типы, включена ли функция в вашей конфигурации. Такие условия — в тексте статьи, примерах и примечаниях.

## Так не пишем

**Столбик опций без `{ | }`.** Если перечислить опции колонки отдельными строками без фигурных скобок, синопсис читается как обязательная последовательность всех опций подряд, хотя каждая из них необязательна и выбирается отдельно.

**Плоский INDEX.** Запись `[GLOBAL | LOCAL]`, `[UNIQUE]`, `[SYNC | ASYNC]` на отдельных строках скрывает, что `GLOBAL` и `LOCAL` — взаимоисключающие ветки, а `UNIQUE` и `SYNC | ASYNC` относятся к ветке `GLOBAL`. Используйте вложенное ветвление, как в примере выше.

## Угловые скобки в типах данных

Угловые скобки встречаются и в именах контейнерных типов: `List<Int32>`, `Optional<String>`, `Struct<name:String>`. Это часть имени типа, а не подстановка. Различайте по контексту: в синопсисе команды `<...>` заменяется вашим значением, в описании типа — переносится в запрос как есть.
