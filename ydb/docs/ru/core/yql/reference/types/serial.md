# Серийные типы данных

Серийные типы данных представляют собой целые числа с автоматической генерацией значений. Если при добавлении строки значение такой колонки не указано, {{ ydb-short-name }} получает его из связанного с колонкой [генератора последовательности (sequence)](../../../concepts/datamodel/sequence.md).

Серийные типы поддерживаются для ключевых и неключевых колонок [строковых таблиц](../../../concepts/datamodel/table.md#row-oriented-tables). В колоночных таблицах этот механизм не поддерживается.

## Типы и диапазоны значений {#types-and-value-ranges}

При [создании таблицы](../syntax/create_table/index.md) для серийной колонки автоматически создаётся sequence. По умолчанию генерация начинается с 1 с шагом 1. Стартовое значение, шаг и позицию генератора можно изменить командой [ALTER SEQUENCE](../syntax/alter-sequence.md).

| Тип           | Максимальное значение | Тип значения |
|---------------|-----------------------|--------------|
| `SmallSerial` | $2^{15}-1$            | `Int16`      |
| `Serial2`     | $2^{15}-1$            | `Int16`      |
| `Serial`      | $2^{31}-1$            | `Int32`      |
| `Serial4`     | $2^{31}-1$            | `Int32`      |
| `Serial8`     | $2^{63}-1$            | `Int64`      |
| `BigSerial`   | $2^{63}-1$            | `Int64`      |

Если доступные значения последовательности исчерпаны, запись с автоматической генерацией значения завершается ошибкой:

```text
Error: Failed to get next val for sequence: /dev/test/users/_serial_column_user_id, status: SCHEME_ERROR
    <main>: Error: sequence [OwnerId: <some>, LocalPathId: <some>] doesn't have any more values available, code: 200503
```

Генератор выдаёт значение до записи строки. При ошибке записи или откате транзакции выданное значение не возвращается генератору, поэтому в колонке могут быть пропуски. Подробнее о выдаче значений и операциях с таблицами см. в статье [{#T}](../../../concepts/datamodel/sequence.md).

## Изменение колонок

Серийная колонка автоматически получает ограничение `NOT NULL`. Текущие ограничения [ALTER TABLE](../syntax/alter_table/columns.md) для таких колонок:

* Нельзя добавить серийную колонку в существующую таблицу через `ADD COLUMN`. Серийный тип нужно указать при создании таблицы.
* Нельзя изменить возможность записи `NULL`, группу колонок (`FAMILY`), а также установить или удалить значение по умолчанию (`DEFAULT`). Параметры генератора изменяются отдельно через [ALTER SEQUENCE](../syntax/alter-sequence.md).
* Неключевую серийную колонку можно удалить через `DROP COLUMN`. Связанный sequence удаляется вместе с ней. Колонку, входящую в первичный ключ, удалить нельзя, как и другие ключевые колонки.

## Пример использования {#usage-example}

{% note info %}

Монотонно возрастающий первичный ключ может создавать неравномерную нагрузку на партиции. Рекомендации по использованию серийных колонок в ключе приведены в статье [{#T}](../../../dev/primary-key/row-oriented.md#monotonic-serial).

{% endnote %}

Создадим таблицу пользователей с составным первичным ключом. Значение `user_hash` вычисляется приложением, например, как хеш адреса `email`. В примере используются условные значения хеша.

```yql
CREATE TABLE users (
    user_hash Uint64,
    user_id Serial,
    name Utf8,
    email Utf8,
    PRIMARY KEY (user_hash, user_id)
);
```

При записи через [UPSERT](../syntax/upsert_into.md), [INSERT](../syntax/insert_into.md) и [REPLACE](../syntax/replace_into.md) без указания `user_id` значение этой колонки генерируется автоматически:

```yql
UPSERT INTO users (user_hash, name, email) VALUES (123456789, 'Alice', 'alice@example.com');
INSERT INTO users (user_hash, name, email) VALUES (987654321, 'Bob', 'bob@example.com');
REPLACE INTO users (user_hash, name, email) VALUES (111111111, 'John', 'john@example.com');
```

Посмотрим строки с помощью [SELECT](../syntax/select/index.md):

```yql
SELECT * FROM users ORDER BY user_id;
```

При последовательном выполнении запросов в новой таблице без других обращений к генератору результат будет следующим:

| user_hash | email               | name  | user_id |
|-----------|---------------------|-------|---------|
| 123456789 | `alice@example.com` | Alice | 1       |
| 987654321 | `bob@example.com`   | Bob   | 2       |
| 111111111 | `john@example.com`  | John  | 3       |

## Явная запись значений {#explicit-values}

Значение серийной колонки можно указать явно, например, при восстановлении данных:

```yql
UPSERT INTO users (user_hash, user_id, name, email) VALUES (222222222, 10, 'Peter', 'peter@example.com');
```

Такая запись обрабатывается как запись обычного целого числа и не изменяет позицию sequence. Генератор не проверяет, какие значения уже есть в таблице, и не пропускает их. Поэтому при последующей автоматической генерации или после `ALTER SEQUENCE RESTART` может быть выдано уже записанное значение.

Для неключевой серийной колонки совпадение значений само по себе не нарушает уникальность первичного ключа. Если серийная колонка входит в ключ, конфликт зависит от совпадения **всего** первичного ключа: `INSERT` завершится ошибкой, `UPSERT` обновит существующую строку, а `REPLACE` заменит её. При смешивании явных и автоматически генерируемых значений позицию sequence нужно согласовать с уже записанными данными через [ALTER SEQUENCE](../syntax/alter-sequence.md).
