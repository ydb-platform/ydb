# Uuid

Модуль `Uuid` предоставляет генераторы первичных ключей для таблиц {{ ydb-short-name }}. В отличие от [`RandomUuid()`](../../builtins/basic.md#random), которая возвращает равномерно случайный [UUID версии 4](https://datatracker.ietf.org/doc/html/rfc4122#section-4.4), эти функции формируют 128-битные значения с осмысленной раскладкой битов так, чтобы порядок ключей и распределение по партициям соответствовали партиционированию {{ ydb-short-name }}.

Все функции возвращают значение типа `Uuid` во внутреннем 16-байтовом представлении {{ ydb-short-name }} (формат Microsoft GUID / mixed-endian). Именно в таком порядке байтов сравниваются первичные ключи. Генераторы, ориентированные на ключи, записывают байты сразу в этом формате вместо формата RFC network-byte-order.

При приведении сгенерированного `Uuid` к типу `Text` получается каноническое текстовое представление GUID. Для ключевых генераторов (`newV8RowKey`, `newV8ColumnKey` и `newV8RowGroup`) получаемая в результате такого преобразования строка не отражает, как именно временная метка и префикс размещены в хранимых байтах.

Необязательные аргументы-зависимости `[T1, ...]` работают так же, как у [`RandomUuid()`](../../builtins/basic.md#random): они управляют моментом вычисления функции для каждой строки, а не содержимым генерируемого значения.

Общие рекомендации по использованию `Uuid` в качестве первичного ключа см. в разделе [UUID в качестве первичного ключа](../../../../dev/primary-key/row-oriented.md#uuid-primary-key).

## Ключевые генераторы {#key-friendly}

Эти функции формируют UUID версии 8 (implementation-specific по [RFC 9562](https://datatracker.ietf.org/doc/html/rfc9562)), оптимизированные для сортировки ключей в {{ ydb-short-name }}. Порядок сортировки определяется сравнением хранимых 16 байтов, а не канонической GUID-строкой.

### `Uuid::newV8RowKey` {#newv8rowkey}

Генерирует ключ для [строчной таблицы](../../../../concepts/datamodel/table.md#row-oriented-tables). При каждом вызове старшие биты (12-битный префикс, 2<sup>12</sup> ≈ 4096 групп значений) остаются случайными, в следующее битовое поле записывается текущее Unix-время с точностью до секунды (по модулю 2<sup>31</sup>), остальные биты заполняются случайностью. Нагрузка на запись распределяется по партициям, а строки, созданные в близкие моменты времени, остаются относительно близко в пространстве ключей внутри своей «корзины» префикса.

* `Uuid::newV8RowKey([T1[, T2, ...]]) -> Uuid`

### `Uuid::newV8ColumnKey` {#newv8columnkey}

Генерирует ключ для [колоночной таблицы](../../../../concepts/datamodel/table.md#column-oriented-tables). Порядок следует времени создания с точностью до секунды (по модулю 2<sup>31</sup>), затем случайным битам суффикса. Строки, вставленные близко по времени, попадают в соседние диапазоны ключей. Колоночные таблицы используют хеш-партиционирование, поэтому отдельный префикс партиции не нужен.

* `Uuid::newV8ColumnKey([T1[, T2, ...]]) -> Uuid`

### `Uuid::newV8RowGroup` {#newv8rowgroup}

Возвращает список из `COUNT` ключей в той же раскладке строчной таблицы, что и `newV8RowKey`, с общим префиксом `PFX`. Строки с общим префиксом обычно попадают в одну партицию — удобно для многострочных транзакций и пакетных вставок.

Первый аргумент может быть:

* `Uint64` — младшие 12 бит используются как префикс;
* `Uuid` — старшие 12 бит MSB исходного значения (внутренний формат YDB) используются как префикс.

`COUNT` имеет тип `Uint64`. Максимальное значение — 1 000 000. Далее могут следовать необязательные аргументы-зависимости.

* `Uuid::newV8RowGroup(Uint64, Uint64[, T1[, T2, ...]]) -> List<Uuid>`
* `Uuid::newV8RowGroup(Uuid, Uint64[, T1[, T2, ...]]) -> List<Uuid>`

### Выбор ключевого генератора {#key-friendly-choice}

| Задача | Функция |
| --- | --- |
| Равномерное распределение по партициям при одиночных вставках в строчную таблицу с некоторой временной локальностью и эффективным кешированием данных | `Uuid::newV8RowKey` |
| Хронологический порядок в первичном ключе колоночной таблицы; локальность по времени в пространстве ключей | `Uuid::newV8ColumnKey` |
| Сокращение количества затрагиваемых партиций при записи множества строк в одной транзакции (строчная таблица) | `Uuid::newV8RowGroup` с одним префиксом |
| Неструктурированные случайные идентификаторы без семантики сортировки | `Uuid::newV4` или [`RandomUuid()`](../../builtins/basic.md#random) |

## Стандартные варианты UUID {#standard}

### `Uuid::newV4` {#newv4}

Равномерно случайный UUID версии 4 (аналог [`RandomUuid()`](../../builtins/basic.md#random) в модуле `Uuid`). Без семантики сортировки и распределения по партициям — для неструктурированных идентификаторов.

* `Uuid::newV4([T1[, T2, ...]]) -> Uuid`

### RFC UUID версии 7 {#rfc-v7}

Функции `Uuid::newV7` и `Uuid::newV7At` генерируют стандартные значения [RFC 9562 UUID версии 7](https://datatracker.ietf.org/doc/html/rfc9562): 48-битная Unix-метка в миллисекундах в старших битах и случайный суффикс. Результат хранится во внутреннем представлении `Uuid` {{ ydb-short-name }}. Используйте их при необходимости совместимости с инструментами RFC v7 или извлечения встроенной временной метки.

Поскольку UUIDv7 следует раскладке байтов RFC, его порядок сортировки в {{ ydb-short-name }} не соответствует хронологии в строковой таблице и в выражении `ORDER BY`. Для производительности таблиц в {{ ydb-short-name }} в первичных ключах предпочтительнее использование `Uuid::newV8RowKey` или `Uuid::newV8ColumnKey`.

### `Uuid::newV7` {#newv7}

Генерирует v7 UUID по текущей временной метке.

* `Uuid::newV7([T1[, T2, ...]]) -> Uuid`

### `Uuid::newV7At` {#newv7at}

Генерирует v7 UUID по явно заданной временной метке. Принимает `Timestamp` или `Timestamp64`.

* `Uuid::newV7At(Timestamp{Flags:AutoMap}[, T1[, T2, ...]]) -> Uuid`
* `Uuid::newV7At(Timestamp64{Flags:AutoMap}[, T1[, T2, ...]]) -> Uuid`

{% note info %}

Исходная метка времени, передаваемая в функцию `Uuid::newV7At`, может быть указана с микросекундной точностью. При этом значения UUIDv7 кодируют метку времени с точностью до миллисекунд. При генерации значения UUIDv7 будет использована метка времени, усеченная до миллисекундной точности.

{% endnote %}

### `Uuid::extractTs` и `Uuid::extractTs64` {#extract-ts}

Извлекают временную метку, встроенную в v7 UUID. Возвращают `NULL`, если аргумент не является UUIDv7 (например, ключ от `newV8RowKey` или `newV8ColumnKey`).

* `Uuid::extractTs(Uuid{Flags:AutoMap}) -> Timestamp?`
* `Uuid::extractTs64(Uuid{Flags:AutoMap}) -> Timestamp64?`

## Примеры {#examples}

Одиночная вставка с ключами строчной таблицы (по умолчанию — случайный префикс на каждую строку):

```yql
INSERT INTO events (id, payload)
SELECT
    Uuid::newV8RowKey(TableRow()) AS id,
    payload
FROM AS_TABLE($rows);
```

Многострочный пакет с общим префиксом (строки обычно попадают в одну партицию):

```yql
$prefix = RandomNumber(1);
$ids = Uuid::newV8RowGroup($prefix, 3ul);

INSERT INTO events (id, payload)
VALUES
    (Unwrap($ids[0]), "a"),
    (Unwrap($ids[1]), "b"),
    (Unwrap($ids[2]), "c");
```

Хронологический первичный ключ для колоночной таблицы:

```yql
INSERT INTO audit_log (id, message)
VALUES (Uuid::newV8ColumnKey(), "user signed in");
```
