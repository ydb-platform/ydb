# UPDATE одной таблицы

status: pending
commit:
id: update
depends: tx-multi-shard

## Сделать

Одна таблица, `WHERE` как у `SELECT`, `SET` литералом или столбцом той же строки. `OPERATION_UPDATE`. Несколько шардов — распределённый commit. `FROM` другой таблицы и присваивание сложнее литерала или столбца той же строки — `0A000`. Таблица с синхронным или уникальным синхронным индексом — `0A000`. Таблица только с асинхронным индексом принимается.

## Тест

Тест: `UPDATE` меняет неключевой столбец. Таблица с синхронным индексом — `0A000`, строка не меняется.

## Готово, когда

Обновлены только названные столбцы таблицы без синхронного индекса.

## Не трогать

- `ydb/core/tx/datashard`, `ydb/core/tx/columnshard` и их протобуфы
- `yql/` и `ydb/core/kqp`: ни `PEERDIR`, ни вызовы
- remote `official`
- код datashard и columnshard в одном читателе

Пока этой возможности нет в коде, она отвечает SQLSTATE `0A000`, текст `not supported`, сессия жива.
## Перед коммитом

```bash
./ya make --build relwithdebinfo -tA ydb/services/sql
```

Коммит только после зелёного прогона. В прогон входят тесты `pg8000`, когда они уже есть.
