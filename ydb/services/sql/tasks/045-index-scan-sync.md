## Сделать

Путь `IndexScan`, если равенство или префикс ключа индекса длиннее префикса PK. Только состояние `Ready`. Чтение impl-таблицы через `TEvRead`, затем точечное чтение основной таблицы. Если список `SELECT` покрыт ключом и `DataColumnNames`, второе чтение не нужно. Цена учитывает оба набора шардов. Среди индексов берётся минимум `total_cost`, PK остаётся кандидатом. `WriteOnly` в перебор не входит. Analyzer запоминает тип, состояние, ключ, покрывающие столбцы и путь impl-таблицы.

## Тест

Тест: `SELECT` по ключу синхронного индекса выбирает IndexScan и возвращает строку. Покрывающий список не читает основную таблицу вторым вызовом, если это видно по плану или по отсутствию лишнего чтения.

## Готово, когда

Ответ совпадает с чтением по PK, путь — индекс.

## Не трогать

- `ydb/core/tx/datashard`, `ydb/core/tx/columnshard` и их протобуфы
- `yql/` и `ydb/core/kqp`: ни `PEERDIR`, ни вызовы
- remote `official`
- код datashard и columnshard в одном читателе

Пока этой возможности нет в коде, она отвечает SQLSTATE `0A000`, текст `not supported`, сессия жива.
## Перед коммитом

```bash
./ya make --build relwithdebinfo -tA ydb/services/sql
```

Коммит только после зелёного прогона. В прогон входят тесты `pg8000`, когда они уже есть.
