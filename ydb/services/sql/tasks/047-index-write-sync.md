# INSERT пишет синхронный индекс

status: pending
commit:
id: index-write-sync
depends: insert-row

## Сделать

Синхронный и уникальный синхронный индекс: строка основной таблицы и строки impl-таблиц в одной транзакции, даже если шарды разные. Занятый ключ уникального индекса — `23505`. Асинхронный индекс сервис не пишет.

## Тест

Тест: `INSERT` в таблицу с синхронным индексом виден через индекс сразу. Повтор уникального ключа — `23505`.

## Готово, когда

Impl-таблица синхронного индекса совпадает с основной сразу после коммита.

## Не трогать

- `ydb/core/tx/datashard`, `ydb/core/tx/columnshard` и их протобуфы
- `yql/` и `ydb/core/kqp`: ни `PEERDIR`, ни вызовы
- remote `official`
- код datashard и columnshard в одном читателе

Пока этой возможности нет в коде, она отвечает SQLSTATE `0A000`, текст `not supported`, сессия жива.
## Перед коммитом

```bash
./ya make --build relwithdebinfo -tA ydb/services/sql
```

Коммит только после зелёного прогона. В прогон входят тесты `pg8000`, когда они уже есть.

## После коммита

В этом файле поставить `status: done` и хеш в `commit`. Правка отметки входит в следующий коммит.
