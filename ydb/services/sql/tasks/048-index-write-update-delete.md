# UPDATE и DELETE пишут синхронный индекс

## Сделать

Снять `0A000` с `UPDATE` и `DELETE` таблицы с синхронным индексом. В той же транзакции удалить старый ключ индекса, если изменились его столбцы, и записать новый. Асинхронный индекс по-прежнему не писать: `ItUsedForWrite` для него ложен.

## Тест

Тест: после `UPDATE` ключа строка находится по новому ключу индекса и не находится по старому. `DELETE` убирает строку из индекса.

## Готово, когда

Основная таблица и синхронный индекс меняются вместе.

## Не трогать

- `ydb/core/tx/datashard`, `ydb/core/tx/columnshard` и их протобуфы
- `yql/` и `ydb/core/kqp`: ни `PEERDIR`, ни вызовы
- remote `official`
- код datashard и columnshard в одном читателе

Пока этой возможности нет в коде, она отвечает SQLSTATE `0A000`, текст `not supported`, сессия жива.
## Перед коммитом

```bash
./ya make --build relwithdebinfo -tA ydb/services/sql
```

Коммит только после зелёного прогона. В прогон входят тесты `pg8000`, когда они уже есть.
