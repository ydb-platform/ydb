# ON CONFLICT по уникальному индексу

status: pending
commit:
id: index-on-conflict
depends: index-write-sync

## Сделать

Цель конфликта — ключ уникального синхронного индекса. Найти строку через impl-таблицу. `DO NOTHING` пропускает. `DO UPDATE` обновляет найденную строку по её PK и правит impl-таблицы затронутых синхронных индексов. Асинхронный индекс целью не бывает. Несовпадение столбцов с ключом — SQLSTATE `42P10`.

## Тест

Тест: конфликт по уникальному индексу с другим PK делает `DO UPDATE` найденной строки, а не вставляет второй PK.

## Готово, когда

В таблице остаётся одна строка, индекс указывает на неё.

## Не трогать

- `ydb/core/tx/datashard`, `ydb/core/tx/columnshard` и их протобуфы
- `yql/` и `ydb/core/kqp`: ни `PEERDIR`, ни вызовы
- remote `official`
- код datashard и columnshard в одном читателе

Пока этой возможности нет в коде, она отвечает SQLSTATE `0A000`, текст `not supported`, сессия жива.
## Перед коммитом

```bash
./ya make --build relwithdebinfo -tA ydb/services/sql
```

Коммит только после зелёного прогона. В прогон входят тесты `pg8000`, когда они уже есть.
