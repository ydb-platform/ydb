# SELECT INTO

status: pending
commit:
id: select-into
depends: insert-select

## Сделать

`SELECT список INTO имя FROM ...` создаёт новую row-таблицу и записывает в неё результат `SELECT`, который сессия уже умеет выполнять. Строки клиенту не отправляются. CommandComplete `SELECT n`. Столбцы и типы берутся из списка выборки; имя — метка `AS`, иначе имя столбца источника. Первичный ключ новой таблицы — первичный ключ источника, если он целиком есть в списке и в том же порядке. Иначе `0A000`, propose не отправляется. Повтор имени — `42P07`, исходная таблица не меняется. Чтение и запись идут одним снимком, как `INSERT ... SELECT`. `TEMPORARY`, `UNLOGGED`, `INTO TABLE` и команда внутри `BEGIN` — `0A000`, таблица не создаётся.

## Тест

Тест через сессию, без сокета: `SELECT id, note INTO copy FROM items WHERE id = 1` создаёт `copy`, следующий `SELECT` из `copy` возвращает ту же строку, исходная таблица на месте. Повтор имени — `42P07`. `SELECT note INTO copy ...` без первичного ключа в списке — `0A000`, таблица не появляется.

## Готово, когда

Новая таблица содержит строки запроса, а клиент получает только число строк.

## Не трогать

- `ydb/core/tx/datashard`, `ydb/core/tx/columnshard` и их протобуфы
- `yql/` и `ydb/core/kqp`: ни `PEERDIR`, ни вызовы
- remote `official`
- код datashard и columnshard в одном читателе

Пока этой возможности нет в коде, она отвечает SQLSTATE `0A000`, текст `not supported`, сессия жива.


Коммит только после зелёного прогона. Тест команды идёт через `TSqlClient`, без кадра протокола.
