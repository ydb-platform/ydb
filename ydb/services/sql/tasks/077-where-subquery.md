## Сделать

Предикат `WHERE` как в PostgreSQL: `IN`, `NOT IN`, `EXISTS`, `NOT EXISTS`, `оператор ANY` и `SOME`, `оператор ALL`, сравнение со скалярным подзапросом. `IN (литерал, ...)` — тот же предикат без второго чтения. Подзапрос без внешнего столбца выполняется один раз. Коррелированный видит столбцы внешнего запроса. Обе таблицы читаются одним снимком. `NULL` внутри `NOT IN` и `ALL` даёт неизвестно, строка не проходит. Скаляр из нескольких строк — `21000`. Несколько столбцов у скаляра и разное число столбцов в `IN` — `42601`.

## Тест

Тест через сессию, без сокета: `WHERE id IN (SELECT id FROM other WHERE id = 1)` возвращает строку. `NOT IN` со списком, где есть `NULL`, её не возвращает. `EXISTS` по пустому подзапросу строку не возвращает.

## Готово, когда

Предикат отбирает те же строки, что такой же `WHERE` в PostgreSQL.

## Не трогать

- `ydb/core/tx/datashard`, `ydb/core/tx/columnshard` и их протобуфы
- `yql/` и `ydb/core/kqp`: ни `PEERDIR`, ни вызовы
- remote `official`
- код datashard и columnshard в одном читателе

Пока этой возможности нет в коде, она отвечает SQLSTATE `0A000`, текст `not supported`, сессия жива.
